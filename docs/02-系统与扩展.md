# 02 · 系统与扩展

> **L2 · 消息怎么走、怎么改。** 上一层：[01 定义与决策](01-定义与决策.md) ·
> 运维见 [03](03-运维与通道.md) · 评测见 [04](04-评测与实验.md)。状态：稳定（未落地项见 §10）。

## 1 · 全局图

```text
platform (QQ / 飞书 / 终端 / …)
   │  收消息
   ▼
adapters/          平台字段 → InboundMessage（纯函数，可离线测）
   ▼
app_core/engine    一轮对话的门面
   ▼
app_core/chat      记忆召回 → prompt 组装 → LLM → 工具循环 → 分段 → 复盘
   ▼
app_core/runner    typing 心跳、节奏、流式发送、时限、同会话串行
   ▼
Channel            发文本 / 发图 / 发语音 / typing
   ▼
platform
```

内核内部再分三层，由 `ops/lint-layers.py` 强制：

| 层 | 职责 | 例子 |
|---|---|---|
| **domain** | 纯规则，不碰 IO | `prompt` `pacing` `delivery` `intent` `mood_domain` `memory_score` `textsim` |
| **orchestration** | 一轮对话、命令、调度 | `engine` `runner` `chat` `chat_turn` `commands` `scheduler` `tool_loop` `memory_port` |
| **infra** | 路径、配置、文件、时钟 | `paths` `config` `files` `kernel/*` |

三条硬约束（lint 守，不靠自觉）：`app_core` 不 import 任何平台框架；
通道声明能力并回传已送达、缓冲或失败。普通回复和主动消息共用内核投递入账入口，会话循环由 `runner` 管理。
完整红线清单见 `AGENTS.md` §4；**分层不物理搬家**，用 docstring 首行 `[domain]` / `[orchestration]` 标记 + lint。

新增平台 = 新增 `adapters/<name>/`，不碰 `app_core` 和 `plugins`（这是 2026-11 第三方 OneBot 实现接连停更后仍成立的保险）。

## 2 · 一轮对话

`TurnRunner.run(msg)` 按 session 取锁 → 立刻亮 typing → `engine.handle` 流式回调 `on_sentence`
→ 边生成边发（段间按 `pacing` 停顿）→ 回合结束补发尾巴、写历史。

- **prompt 顺序**：稳定前缀（画像）→ 历史 → 【背景】块（记忆 / 笔记 / 技能 / 纠正 / 待办）。
  画像作前缀是为了缓存；记忆放历史之后是为了不让前缀每轮变化。总预算 1200 字，超了先丢待办/纠正/技能/笔记。
- **语气**：默认 model-first + 信号包，规则只兜底；`chat.style_mode=model` / `chat.context_format=compact`。
- **工具循环**：最多 6 轮（`llm.max_tool_rounds`），每多一轮多一次完整 LLM 调用（约 +1.5s）；
  轮数用尽时去掉工具再问一次，保证仍有正文。实现见 `app_core/tools.py`，
  **加工具必须同时改 `TOOLS` schema 与 `HANDLERS`（模块加载时自检两边一致）**。
- **时限与并发**：`runner.py` 的 watchdog 管两件事——`reply_deadline=90` 是宽松总上限
  （只防「永远不结束」），`reply_stall_seconds=30` 是**无进展超时**（发出首句后久无新句子才收尾）；
  QQ 和飞书私聊先收集一轮输入。默认停顿 2 秒后开始回复，连续输入最多从首条等 4 秒；已开始处理的回合之后，新收到的短时间补充合并成下一轮。不同引用对象各自处理。用 `chat.text_settle_seconds: 0` 可关闭纯文本等待。
  取证不受 stall 约束，可选取数共享 `first_token_budget=10`。`[latency]` 记录收件到首段确认，日志可交给 `ops/latency-report.py` 汇总。工具预算从首字预算
  派生，不再被总闸绑架（旧公式 `deadline/3` 会在放宽总闸后悄悄把单工具超时从 15s 抬到 30s）。
  `_SESSION_LOCKS` 按 session 串行。超时由插件补记已发段落 + 收尾一句，不再让用户「再说一遍」。
  **这些都是实现细节，不是项目定义**（01 §6）；影子实验与判据见 [04](04-评测与实验.md)。
- **私聊隔离**：主人 / 外人两份人格（`persona.json` / `persona-stranger.json`），
  `PUBLIC_TOOLS` 只有 `web_search` 与 `meme_send`；外人纠正写进本人 corrections。

## 3 · 通道协议

`app_core/message.py` 的 `Part(form, content, meta)` 让形式成为数据而不是附加字段：
入站语音 = `Part("voice", "转写文本")`，出站语音 = `Part("voice", "/tmp/v.silk")`，
「这句用说的」= 两条不同 form 的 Part。

`Channel` 只声明 `forms: set[str]` 与 `send_part / typing`；平台不支持的 form 由 runner 降级
（voice → text，drawing → image）。参考实现 `adapters/console.py`；
QQ / 飞书的接入与配置见 [03](03-运维与通道.md)。

## 4 · 记忆与知识闭环

**写入两个时机**：批量总结（8 轮 / 40 条 / 闲置 30 分钟）与 POST_WRITE 阶段的即时自述；
另有纠正后台写入、周度反思两个旁路。事实 → 向量化 → 按需召回；
矛盾时 `supersede` 软删旧事实（不物理删）；超阈值归档而非消失。

**召回**：dense 单通道，`recall_min_score=0.35` 硬切，注入【背景】块。
BM25 / 实体图 / 二次召回目前全是**影子**，不改返回值——判据与截止日见 [04](04-评测与实验.md)。
按 01 的定义，下一步是「先判断这轮要不要回忆」的检索门控。

**清理**：`importance ≥0.8` 保留半年、`0.5–0.8` 三个月、`<0.5` 一个月；
近似重复窗口 10 分钟；矛盾判定余弦 ≥0.5、≥0.6 才改、每轮最多 2 条。

**知识**：`learn/raw/` 与 `learn/notes/*.md`；价格 14 天 / 版本 30 天时效；
周日 20:30 巡检、周检 ≤5 页、月 1 号清理 ≤20 页。

## 5 · 情绪、主动消息、群聊

- 情绪三值（心情 / 基线 / 精力），时间常数 τv=5h / τb=72h / τe=8h；23:55 快照留 400 天。
  情绪只改语气与长度，不污染事实。
- **主动消息只在「有 followup 话头」时开口**：候选池窄（只跟进未完成事项）+ 匹配窄（2-gram ≥0.7）。
  目前主动消息只走 QQ，飞书侧仅「你发它回」。
- 群聊独立链路、**默认关闭**：20 条上下文、3 条/分、5s 冷却、日 5 万 token 上限。

## 6 · 数据布局与配置

| 路径 | 内容 |
|---|---|
| `/opt/nonebot/data/chat.db` | 对话历史、任务、统计 |
| `/opt/qqbot-data/livingmemory.db` | 文档 / 原子事实 / 向量 |
| `data/persona*.json`、`watchlist.json` | 人格两份、巡检话题（最多 8 个，免重启） |
| `data/prompt_log`、`alerts.jsonl`、`data/shadow-*.jsonl` | 最近 prompt、告警、影子采样 |
| `/opt/qqbot-data/keys.json` (600) | 凭证，**不入库、不随部署传输** |

关键默认值（`app_core/config.py` 的 `DEFAULTS`，完整表见 `nonebot/config.example.yaml`）：
`llm.temperature=1.15`、`llm.max_tokens=1000`、`llm.reply_deadline_seconds=90`、
`llm.reply_stall_seconds=30`、`llm.first_token_budget_seconds=10`、
`llm.max_tool_rounds=6`、`llm.thinking_casual=false`、
`context.history_max_chars=2500`（无纪要 4000）、`context.summary_idle_minutes=30`、
`memory.contradiction_check=on`（off / shadow / on）、`memory.shadow_retrieval=false`、
`memory.recall_gate=off`（off / shadow / on，影子截止 2026-11-30）、
`chat.context_format=compact`、`chat.budget_mode=legacy`（legacy / tiered，默认不改变 prompt 基线）、
`chat.shadow_followup=true`、`chat.shadow_sample=0.3`、`chat.media_settle_seconds=1.5`、
`tools.require_approval=false`（授权门，默认关）、`proactive.channel=qq`（默认 QQ，发不出去回退）、
`image.max_side=1600`、`meme.threshold_*=0.12/0.16/0.08`、`group.*` 默认关闭。

`tools.py` 的 `READ_ONLY_TOOLS` 决定「同轮能否并发」。批次 4 把 `web_open` 移出名单：
它会 `learn.note_write` 往知识库写笔记，放进并发组等于允许两个写操作同时落盘。
写类工具统一走串行 + 审计（`app_core/audit.py`）。

改 `config.yaml` 后**须重启**（`config.load` 有进程内缓存）；人格用 `/reload_persona`，`watchlist.json` 免重启。

## 7 · 加东西的五条路径

| 要加什么 | 改哪里 | 检查 |
|---|---|---|
| 业务模块 | `app_core/<name>.py`，docstring 首行标层 | `lint-layers` |
| 通道 | 实现 `Channel` 三原语，用 `TurnRunner` | `test-runner` + 该通道离线测试 |
| 命令 | `app_core/help.py` 登记 + 插件 handler；新通道用 `commands.default_registry` | `lint-plugins` + `test-commands` |
| LLM 工具 | `TOOLS` 加 schema + `HANDLERS` 加实现（名字必须一致） | `smoke-all` |
| 定时任务 | `scheduling/scheduler.py` 的 `JOBS` + `_run_job` 分支 | `smoke-all` / `smoke-clock` |
| 配置项 | `config.DEFAULTS` + `config.example.yaml` + `ops/config-ui.py` 键表 | `test-config-ui` |

常见错误：`plugins/` 里直接 `import app_core.chat`（通过 `companion_core.shared_application()` 取得宿主实例）；
新建平行模块而不是注册进 `HANDLERS`；测试写死日期（必须从 `time.time()` 派生）。

## 9 · 为什么没有多步任务 agent

`agentd`（计划分解 + 沙箱 + 产物清单）于 **2026-11-10 删除**，理由是维护成本大于收益、
且当时没有审计层。按 01 的「可授权性」，现在是**补审计层后放开可授权短任务**，
而不是永远放弃执行能力；仍然**不做无人监督的自主规划与不可逆执行**。
前置条件：每次副作用可追溯、可回滚（`approval.py` / `alerts.jsonl` / 配置备份回滚已有基础）。
