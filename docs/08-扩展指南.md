# 扩展指南

> 五条扩展路径。每条都写清「改哪个文件、照着谁抄、跑哪个检查」。
> 规范不是靠自觉：改错了 `ops/lint-*.py` 会红。

## 0. 通用规则

- 业务逻辑进 `app_core/`，平台相关放 `adapters/` 或 `plugins/`。
- 新模块的 docstring 首行标层：`[domain]` 或 `[orchestration]`。
- 改完跑第 1 节的 8 条检查（或 `ops/verify.sh`）。
- CHANGELOG 加一条：改了什么、为什么、验证数字。

## 1. 加一个业务模块

**放哪**：`nonebot/app_core/<name>.py`

```python
"""[domain] 一句话说明这个模块干什么。

为什么单独一层/为什么这么实现——写决策，不写流水账。
"""
from __future__ import annotations

# domain 只能 import domain / infra
```

**选层**：
- 纯计算、不读写文件/数据库 → `[domain]`
- 要查库、调多个模块、响应一次事件 → `[orchestration]`
- 只提供路径/配置/IO 原语 → 放 infra（`paths` / `config` / `files`）

**检查**：`python ops/lint-layers.py`（domain 反向依赖会红）。

**常见错误**：在 domain 里 `import sqlite3`、`from app_core import runner`。

## 2. 加一个通道

**照着抄**：`nonebot/adapters/console.py`（完整参考实现）。

```python
class MyChannel:
    async def send_text(self, session: str, text: str) -> bool: ...
    async def send_image(self, session: str, path: str) -> bool: ...
    async def typing(self, session: str, on: bool) -> None: ...

async def on_message(platform_msg):
    msg = InboundMessage(
        session=f"myplat:{platform_msg.user_id}",
        text=platform_msg.text,
        images=platform_msg.images,
        platform="myplat",
    )
    await TurnRunner(engine, MyChannel(), deadline=45).run(msg)
```

**可选能力**：命令用 `commands.default_registry(core)`；定时用 `runtime.start_background`；
主动消息用 `ProactiveRuntime(core, send).run()`。

**检查**：`ops/test-runner.py`（流式/typing/超时）；新通道自己补一条 e2e。

**常见错误**：在 adapter 里做耗时 IO（下载文件）——那是插件/入口的事。

## 3. 加一个命令

1. `app_core/help.py`：日常组或 `DEBUG_GROUPS` 里登记（名字 + 说明）。
2. QQ：`plugins/commands|admin` 里 `on_command` + handler。
3. 新通道：`commands.default_registry` 里加一条，或自己注册 `CommandSpec`。

**检查**：`ops/lint-plugins.py`（注册了没写、写了没注册都会红）+ `ops/test-commands.py`。

**常见错误**：只加 `on_command` 不改 `help.py`——lint 直接 FAIL。

## 4. 加一个 LLM 工具

**只改两处**：

1. `tools.py` 的 `TOOLS`：加 JSON schema（名字、描述、参数）。
2. `tools.py` 的 `HANDLERS`：加 `"name": _impl`，实现签名 `async def _impl(core, args, images) -> str`。

模块加载时会自检两边名字是否一致，不一致直接抛 `RuntimeError`。

**检查**：`ops/smoke-all.py` 会遍历所有工具调用一遍。

**常见错误**：只加 schema 不加实现（加载就炸）；实现里抛异常不兜（`execute` 会包一层，但语义要自己保证）。

## 5. 加一个定时任务

1. `scheduling/scheduler.py` 的 `JOBS` 加一行：`("name", 时, 分, 补跑窗口)`。
2. `_run_job` 加分支（名字 → 具体动作）。

**检查**：`ops/smoke-all.py`（逐个 `_run_job`）、`ops/smoke-clock.py`（真实时钟）。

**注意**：新任务自动进 `missing_jobs` 审计（JOBS 表遍历），漏跑会被 `job-audit` 发现。

## 6. 加一个配置项

1. `app_core/config.py` 的 `DEFAULTS`：加键 + 默认值 + 注释。
2. `nonebot/config.example.yaml`：同步（lint 会比对键覆盖）。
3. `ops/config-ui.py` 的键表：加中文说明（面板才显示）。

**检查**：`ops/lint-plugins.py`（配置键漂移）+ `ops/test-config-ui.py`。

## 7. 不要做的事

| 别做 | 原因 |
|---|---|
| 在 `app_core` import nonebot | 内核要能脱离框架跑，lint 会拦 |
| 插件直接 `import app_core.chat` | 走 `from plugins.chat import core` + `CORE_API` |
| 绕过 `HANDLERS` 新写一套工具分发 | 两套实现会分叉 |
| 在 domain 里读写文件/数据库 | 单测要起 IO，分层失效 |
| 加平行模块而不是扩展注册表 | 下次改的人找不到 |
| 改已定决策不写原因 | CHANGELOG 要求；否则被当默认值 |
