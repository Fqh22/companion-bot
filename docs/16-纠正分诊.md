# 纠正分诊：当场识别，后台判断，三类去处

> 目标：他说「不是这样」之后，下一轮不能还按错的来。
> 难点不是「什么时候写」，是「写什么、写到哪」。

## 一、三类去处

| 判定 | 去处 | 是否注入 prompt |
|---|---|---|
| 事实纠正，可验证断言 | `MemoryPort.remember` + 矛盾闸 | 走召回，不进 corrections |
| 行为纠正（怎么说话） | `corrections.md` | 每轮注入（现有 lessons 段） |
| 提不出来但像事实 | `data/corrections_pending.jsonl` | **永不注入**，等复盘 |
| 复盘也提不出来 | `data/corrections_unverified.jsonl` | **永不注入**，只留档 |

行为清单是**行动规则**，所以只有模型明确判 `kind=behavior` 才能进去。
「提不出来」不等于「行为纠正」——未知不许伪装成已知。

## 二、判断 schema（一个分类法，两个写入方）

```json
{
  "is_correction": true,
  "kind": "fact | behavior | none",
  "claim": "他生日是 3 月",
  "confidence": 0.8,
  "why": "他明确否定了上一轮说的 2 月"
}
```

- `is_correction=false` → 不写任何地方，只记候选日志；
- `fact` 且 `confidence>=0.7` 且 `claim` 非空 → 记忆；
- `behavior` → corrections.md；
- `fact` 但置信不足 / claim 为空 → pending。

**误报靠上下文压**：prompt 必须带「上一轮 assistant 的原文」，并明确
「只有他在否定你刚才说的内容才算纠正；讨论里说『不对』但不是说你，不算」。

## 三、时序

```
用户这句话
  → 当场：命中 CORRECTION_HINTS + 上一轮有 assistant
  → 记一条候选（不阻塞回复）
  → 后台：一次小模型调用，输出上面的 schema
  → 分流：记忆 / corrections / pending
```

当场**不同步写记忆**：矛盾检测要问一次模型，塞进回合会吃 45 秒预算。
照图注的模式：回复照常发，后台任务幂等跳过。

## 四、幂等：range_key 按 claim 哈希

`memory_store.add_document` 的 `range_key` 是**整条写入级**排他键
（`memory_ranges` 命中即跳过）。所以不能用 `corr:<日期>`——同一天第二条纠正会被吞。

用 `range_key="corr:" + sha1(归一化 claim)[:16]`：

- 同一条纠正被当场和复盘各写一次 → 哈希命中，跳过；
- 换说法（「生日是三月」vs「他生日3月」）→ 哈希不同，由第二层 24h 相似度查重兜。

## 五、复盘

- 复盘处理 pending：重试一次判断，成功分流；失败 3 次移到 `corrections_unverified.jsonl`；
- 复盘水位新建：`data/review_state.json` 记录 `last_pending_ts`，
  不用钟表窗（复盘晚点/漏跑会漏查重）；
- 复盘写入 corrections 前，先查 pending/记忆里同主题，跳过重复。

## 六、验收

- 说「我生日是 3 月不是 2 月」→ 下一轮问生日答 3 月；
- 说「别只顺着说」→ 不进记忆，只进 corrections；
- 说「不对，这个方案…」（不是纠正 AI）→ 不写任何地方；
- 同一天两条不同纠正 → 都写入，不被 range_key 吞；
- pending/unverified 不出现在任何 prompt 里。
