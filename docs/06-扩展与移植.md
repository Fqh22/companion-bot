# 扩展与移植

> 一句话：**内核在 `app_core`，QQ 只是第一个接进来的通道。**
> 换平台不是重写项目，是写一个适配器；加东西不是改散落各处，是走五条路径。

## 为什么留这条路

QQ 个人号没有官方机器人 API。现在的接入靠 OneBot v11 实现（SnowLuma / NapCat 等），
它们逆向 QQ 私有协议。2026-11 腾讯已向相关实现发律师函，通道可能随时停更、失效或下架。

所以分层不是「洁癖」，是**保险**：把「怎么说话」和「从哪说话」分开。

## 分层

| 层 | 职责 | 模块 | 允许依赖 |
|---|---|---|---|
| **domain** | 纯规则：分段、拼 prompt、算情绪、解析意图 | `delivery` `pacing` `prompt` `intent` `textsim` `vec` `memory_score` `mood_domain` `followup_domain` `memory_common` | domain / infra |
| **orchestration** | 编排：一轮对话、命令、调度、契约 | `engine` `runner` `commands` `runtime` `introspect` `chat` `chat_turn` `memory_port` `tool_loop` `scheduler` `proactive` `learn` `memory` … | domain / infra / 同层 |
| **infra** | 路径、配置、文件、时钟、数据库 | `paths` `config` `files` `kernel/*` | 不依赖业务 |

上层文档里的 `[domain]` / `[orchestration]` 就是层标记，写在模块 docstring 第一行。

**哪层懂平台**：只有 `adapters/` `plugins/` `bot.py` 懂；上面三层一行 `import nonebot` 都没有。
可复用的是上层（约 1.1 万行），要重写的是下层（约 2 千行）。

## 规则

1. **domain 不得 import orchestration**（否则纯规则绑上会话状态，单测要起半个系统）。
2. **adapters 只走门面**：`engine` / `runner` / `commands` / `delivery`；禁止 `chat` / `chat_turn` / `tool_loop`。
3. **kernel 不反向依赖业务包。**
4. 外包模块（`web` `asr` `llm`）只允许 `chat` `chat_turn` `memory` `tools` `engine` `group` 这几处 import（见 [10-设计决策](10-设计决策.md)）。

**怎么查**：

```bash
python ops/lint-layers.py      # 纯 AST，秒级
```

反向验证过：给 `pacing.py` 加一行 `from app_core import runner`，lint 立即 FAIL。它不会「永远绿」。

## 一个通道只需要三件事

```python
# app_core/runner.py
class Channel(Protocol):
    async def send_text(self, session: str, text: str) -> bool: ...
    async def send_image(self, session: str, path: str) -> bool: ...
    async def typing(self, session: str, on: bool) -> None: ...
```

其余由 `TurnRunner` 负责：typing 心跳、流式分段、段间停顿、45 秒硬线、补发尾巴。
参考实现：`adapters/console.py`（终端）、`plugins/chat` 里的 `QQChannel`。

```python
async def on_message(platform_msg):
    msg = InboundMessage(
        session=f"myplat:{platform_msg.user_id}",
        text=platform_msg.text, images=platform_msg.images, platform="myplat")
    await TurnRunner(engine, MyChannel(), deadline=45).run(msg)
```

## 两条路线

**A. 还在 NoneBot 里换平台**（Telegram / Discord / 飞书）
1. 装对应 adapter；
2. 写 `to_inbound(event)`，平台字段 → `InboundMessage`；
3. 改 `QQChannel` 的发送方法；
4. 命令/权限沿用（`SUPERUSER` 换成平台用户判定）；
5. 定时/主动消息原样可跑。

**工作量 3–5 天**，`plugins/chat` 主体不用动。

**B. 完全不用 NoneBot**（Web / 桌面 / 自建服务）
1. 入口循环：收消息 → `InboundMessage` → `TurnRunner`；
2. 命令：`commands.default_registry(core)` 提供 11 条，`dispatch("/mood", ctx)`；
3. 定时：`runtime.start_background(core, send)`；
4. 主动消息：`ProactiveRuntime(core, send).run()`；
5. 审批：`approval.ApprovalPort` 是协议，实现「发消息问 + 等回复」。

**工作量约 1 周**，剩下的是通道 IO 与审批。

## 加东西的五条路径

| 加什么 | 改哪里 | 检查 |
|---|---|---|
| **业务模块** | `app_core/<name>.py`，docstring 标 `[domain]`/`[orchestration]` | `lint-layers` |
| **通道** | 实现 `Channel` 三原语（抄 `console.py`） | `test-runner` |
| **命令** | `help.py` 登记 + 插件 handler；新通道用 `default_registry` | `lint-plugins` + `test-commands` |
| **LLM 工具** | `TOOLS` schema + `HANDLERS` 实现（两边名字一致，加载自检） | `smoke-all` |
| **定时任务** | `scheduler.JOBS` 加一行 + `_run_job` 分支 | `smoke-all` / `smoke-clock` |
| **配置项** | `config.DEFAULTS` + `config.example.yaml` + `config-ui` 键表 | `lint-plugins` + `test-config-ui` |

**选层**：只做计算 → domain；要查库/串模块 → orchestration；只提供路径/配置 → infra。
拿不准先放 orchestration——domain 的边界越窄越好守。

## 不要做的事

| 别做 | 原因 |
|---|---|
| 在 `app_core` import nonebot | 内核要能脱离框架跑，lint 会拦 |
| 插件直接 `import app_core.chat` | 走 `from plugins.chat import core` + `CORE_API` |
| 绕过 `HANDLERS` 新写一套工具分发 | 两套实现会分叉 |
| 在 domain 里读写文件/数据库 | 单测要起 IO，分层失效 |
| 加平行模块而不是扩展注册表 | 下次改的人找不到 |
| 改已定决策不写原因 | CHANGELOG 要求；否则被当默认值 |
