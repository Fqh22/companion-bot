# 对话与工具

> 一轮回复里，工具是怎么被调起来的、边界在哪、为什么没有"多步任务 agent"。

## 工具循环

一轮回复最多 **6 轮**工具调用（`llm.max_tool_rounds`），每多一轮多一次完整 LLM 调用（约 +1.5s）。
总时限 **45 秒**（`llm.reply_deadline_seconds`），超时回一句"有点卡"，不让用户干等。

轮数用尽时，程序会**去掉工具再问一次**，保证仍有正文返回——不会出现"只调工具、不回复"。

工具实现只有一份：`app_core/tools.py` 的 `HANDLERS`（名字 → 实现）。
加工具只改两处：`TOOLS` 的 schema + `HANDLERS`；模块加载时自检两边一致。

## 工具清单（13 个）

| 类型 | 工具 | 说明 |
|---|---|---|
| 记忆 | `memory_read` / `memory_search` | 全文读 / 召回 |
| 知识 | `note_write` / `note_list` / `kb_read` / `kb_search` | 写笔记、读页面、语义搜 |
| 日记 | `diary_read` | 读某天日记 |
| 提醒 | `remind_me` / `remind_list` / `remind_cancel` | 定时提醒 |
| 网络 | `web_search` / `web_open` | 搜索 / 打开网页 |
| 表情 | `meme_send` | 发表情包 |

**公共工具**只有 `web_search` 和 `meme_send`（`PUBLIC_TOOLS`）：陌生人不能读他的记忆、笔记、日记。

## 任务与提醒

- `reminders` 表：到点由调度器发消息，发完关闭；
- `followups`：从对话里抽出的"待跟进事项"，主动消息用它决定"有没有话头"；
- `scheduler`：日记、复盘、清理、周报，带补跑窗口和缺跑审计。

这三样属于**任务记忆**，目前**不在 MemoryPort 契约里**（见 `docs/09` 的 3/5）。
它们能正常工作，只是入口仍走旧路径。

## 为什么没有多步任务 agent

曾经有过（`agentd`：计划分解 + 沙箱执行 + 产物清单），2026-11-10 删除。原因不是技术不可行，
是**维护成本大于收益**：单用户、串行请求，多步编排带来的价值主要是"架构好看"。

如果将来要做，前置条件是先有**审计层**（每次副作用可追溯、可回滚）。
没有审计层就上执行能力，等于把不可逆的风险交给一个没有责任边界的程序。
