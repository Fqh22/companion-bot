## 文档约定

- **中文写作**：先给结论，再给理由；命令和输出贴实际值，数字标注日期。
- **引用代码**：写路径和行号（如 `app_core/chat.py:1042`），不要只说"在 chat 里"。
- **数字来源**：测试规模、成本、延迟这类数字必须来自实测；改了测试要顺手更新。
- **状态标注**：稳定 / 设计稿 / 进行中 / 归档。设计稿不能当作已实现来引用；归档文档保留沿革，不再作判据。
- **新增文档**：先在这张表登记，再写内容；不要起孤立文件。
- **改文件名**：需要同步更新代码注释、README、AGENTS、CHANGELOG 与本文档，并跑
  `ops/verify.sh` 与链接检查（仓库内所有相对链接必须可解析）。
