# 移植指南：QQ 只是一个通道

> 一句话：**业务逻辑在 `app_core`，QQ 只是第一个接进来的通道。**
> 换平台不是重写项目，是写一个适配器。

## 为什么要留这条路

QQ 个人号没有官方机器人 API。现在的接入靠 OneBot v11 实现（SnowLuma / NapCat 等），
它们逆向 QQ 私有协议。风险不是理论上的：2026-11 腾讯已向相关实现发律师函，
通道可能随时停更、失效或下架。

所以这个项目的分层不是「洁癖」，是**保险**：把「怎么说话」和「从哪说话」分开。

## 分层：哪一层懂平台

| 层 | 目录 | 懂 QQ/NoneBot 吗 | 换通道要动吗 |
|---|---|---|---|
| 业务核心 | `nonebot/app_core/` | ❌ 一行 `import nonebot` 都没有（lint 在守） | 不动 |
| 通道无关循环 | `app_core/runner.py` | ❌ 只认 `Channel` 三个原语 | 不动 |
| 引擎门面 | `app_core/engine.py` | ❌ `InboundMessage → handle → OutboundMessage` | 不动 |
| 平台适配 | `nonebot/adapters/` | ✅ | **重写/新增一个** |
| 平台胶水 | `nonebot/plugins/` | ✅ NoneBot 的 `on_message/on_command` | 复用或重写入口 |
| 进程入口 | `nonebot/bot.py` | ✅ NoneBot 启动 | 重写 |

**可复用的是上面三层（约 1.1 万行），要重写的是下面三层（约 2 千行）。**

## 一个通道只需要实现三件事

```python
# app_core/runner.py
class Channel(Protocol):
    async def send_text(self, session: str, text: str) -> bool: ...
    async def send_image(self, session: str, path: str) -> bool: ...
    async def typing(self, session: str, on: bool) -> None: ...
```

其余全部由 `TurnRunner` 负责：typing 心跳、流式分段、段间停顿、45 秒硬线、补发尾巴。

参考实现见 `nonebot/adapters/console.py`（终端）和 `plugins/chat` 里的 `QQChannel`（QQ）。

## 最小可运行通道

```python
from app_core.engine import Engine, InboundMessage
from app_core.runner import TurnRunner

class MyChannel:
    async def send_text(self, session, text):
        await my_platform.send(session, text)
        return True

    async def send_image(self, session, path):
        await my_platform.send_image(session, path)
        return True

    async def typing(self, session, on):
        await my_platform.set_typing(session, on)   # 不支持就 pass

async def on_message(platform_msg):
    msg = InboundMessage(
        session=f"myplat:{platform_msg.user_id}",
        text=platform_msg.text,
        images=platform_msg.images,
        platform="myplat",
    )
    await TurnRunner(engine, MyChannel(), deadline=45).run(msg)
```

**这就完了。** 记忆、情绪、prompt、分段、投递策略、45 秒硬线全部复用。

## 两条路线

### 路线 A：还在 NoneBot 里换平台（Telegram / Discord / 飞书…）

1. 装对应的 nonebot adapter；
2. 在 `adapters/` 写一个 `to_inbound(event)`，把平台字段映射成 `InboundMessage`；
3. 图片/文件发送改 `QQChannel` 里那两个方法（NoneBot 的 `MessageSegment` 按平台不同）；
4. 命令/权限沿用 NoneBot（`SUPERUSER` 换成平台的用户 id 判定）；
5. 定时/主动消息的 `driver.on_startup` 原样可跑。

**工作量：3–5 天。** `plugins/chat` 的主体不用动。

### 路线 B：完全不用 NoneBot（Web / 桌面 / 自建服务）

1. 写一个入口循环：收消息 → `InboundMessage` → `TurnRunner`；
2. 命令分发：`app_core/help.py` 已经是命令清单的唯一真相源，照它写一个 `/xxx` 分发表；
3. 定时任务：`app_core/scheduling/scheduler.py` 的 `JOBS` 和 `_due()` 是纯逻辑，自己起一个每分钟的循环；
4. 主动消息：`app_core/proactive.py` 是纯判断，自己起一个 30 分钟的循环；
5. 审批：`app_core/approval.py` 的 `ApprovalPort` 已经是协议，实现一个「发消息问 + 等回复」。

**工作量：1–2 周。** 但业务代码一行不改。

## 数据迁移（容易漏）

| 数据 | 位置 | 换通道要注意 |
|---|---|---|
| 对话历史 | `data/chat.db` | `session` 是 `private:QQ号`，换通道后要映射 |
| 长期记忆 | `qqbot-data/livingmemory.db` | 同上，documents 里带 session |
| 学习资料 | `qqbot-data/workspace/learn/` | 与平台无关，直接搬 |
| 人格 | `data/persona.json` | 与平台无关 |
| 配置 | `config.yaml` | 通道相关键要换 |

**建议**：新通道的 session 用 `平台:会话` 前缀（`tg:private:123`），
旧数据保留 `private:` 不动——记忆召回不依赖前缀，历史读取可以兼容两种。

## 通道能力清单

| 能力 | 现在（QQ） | 新通道 MVP 必需？ |
|---|---|---|
| 文本收发 | ✅ | ✅ |
| 分段发送 | ✅（18–32 字） | ✅（`Capability.max_text_chars` 可配） |
| 图片收发 | ✅ | 建议 ✅ |
| 文件收发 | ✅ | 可选 |
| 语音 | ❌（已下线） | 可选 |
| 「正在输入」 | ✅（`set_input_status`） | 可选（不支持就空实现） |
| 引用回复 | ✅（默认关） | 可选 |
| 命令 | ✅ `/help` 29 条 | ✅（照 `help.py` 写） |
| 主动消息 | ✅ | 建议 ✅ |
| 定时任务 | ✅ | ✅（日记/复盘/备份） |

## 需要留意的硬编码点

换通道时按这张表搜：

- `MessageSegment`（图片/引用/表情包）→ 平台的富消息 API
- `bot.call_api`（下载文件、get_record）→ 平台的媒体接口
- `SUPERUSER` / `event.user_id` → 平台的身份体系
- `private:xxx` / `group:xxx` session 前缀
- `Capability(name="qq", ...)` → 新平台的限制（字数/分段/图片大小）

## 一句话

**QQ 是演示，不是底座。** 底座是 `app_core` + `Engine` + `TurnRunner`：
它们不知道 QQ 的存在，也不打算知道。
