> 2026-11-15 决定：从 QQ 再分出一条飞书通道。QQ 继续跑，等飞书稳定一周后再决定是否下线。
> 个人微信不做（无个人号官方 API，注入/协议都违规且封号风险高）；企业微信可行但门槛与体验差。

## 一、为什么是飞书

| 维度 | 飞书 | 企业微信 | 个人微信 |
|---|---|---|---|
| 官方能力 | 开放平台 + 机器人 | 自建应用（企业内部） | 无个人号 API |
| 个人能否开通 | 手机号建租户，免费版够用 | 可注册未认证企业，认证要营业执照/对公打款 | — |
| 收消息 | **长连接，无需公网 IP/域名/内网穿透** | 回调 URL（认证企业要备案域名） | 逆向协议 |
| 主动发消息 | 可以 | 可以 | 违规 |
| 账号风险 | 低 | 中（审核/回调中断/Token 刷新） | 高（封号） |

关键点：
- 飞书长连接只需服务器能访问公网；事件要在 3 秒内处理完；长连接仅支持企业自建应用。
- 飞书语音消息是 `msg_type=audio`，文件必须上传为 `file_type=opus` 并带 `duration`（毫秒）。
  我们的 TTS 出的是 QQ 专用 silk，接飞书要转 opus（云端已有 ffmpeg）。
- 飞书机器人没有「正在输入」状态 → `Channel.typing` 空实现，45 秒硬线与分段逻辑不变。

## 二、一次性配置（人来做，约 10 分钟）

1. 打开 https://open.feishu.cn/app ，用飞书账号登录
2. 「创建企业自建应用」→ 填名称/描述/图标
3. 「添加应用能力」→ 添加「机器人」
4. 「权限管理」添加：`im:message`、`im:message:send_as_bot`、`im:resource`、`im:chat`
5. 「事件与回调」→ 事件配置 → 订阅方式选 **使用长连接接收事件**
   → 添加事件 `im.message.receive_v1`
6. 「版本管理与发布」→ 创建版本 → 可用范围选「仅自己」→ 发布
7. 回到飞书客户端，搜索应用名，打开机器人私聊

凭证只放云端（不进仓库）：

```bash
# /opt/qqbot-data/keys.json（600），加一个 feishu 对象
{"deepseek": "...", "zhipu": "...", "feishu": {"app_id": "cli_xxx", "app_secret": "xxx"}}
```

## 三、探针（已完成 2026-11-15 22:17）

> 状态：**回环已通**——飞书私聊「在吗」→ 云端日志 `recv chat_type=p2p …` →
> 飞书收到「探针收到：在吗」。下一步已接内核（见第四节，插件 `plugins/feishu`）。

接内核之前先跑 `ops/feishu-probe.py`：只验证「长连接能收私聊 + 能回一条文本」，
不依赖 nonebot / app_core，不写生产数据。

云端探针环境（独立 venv，别装进 nonebot 的 venv）：

```bash
sudo mkdir -p /opt/feishu-probe-venv && sudo chown ubuntu:ubuntu /opt/feishu-probe-venv
python3 -m venv /opt/feishu-probe-venv
/opt/feishu-probe-venv/bin/pip install -r /opt/nonebot/ops/requirements-feishu.txt
```

运行与验收：

```bash
/opt/feishu-probe-venv/bin/python /opt/nonebot/ops/feishu-probe.py --check   # 凭证格式
nohup /opt/feishu-probe-venv/bin/python /opt/nonebot/ops/feishu-probe.py > /tmp/feishu-probe.log 2>&1 &

# 在飞书私聊机器人发一句「在吗」，验收：
#   /tmp/feishu-probe.log 出现 recv chat_type=p2p … text='在吗'
#   飞书里收到「探针收到：在吗」
tail -f /tmp/feishu-probe.log
```

## 四、接内核（已实现，2026-11-15）

- `nonebot/adapters/feishu.py`：事件 → `InboundMessage`（`session=feishu:<open_id>`，
  私聊只和你聊；图片/语音下载到临时文件），`FeishuChannel` 实现
  `send_text/send_image/send_voice` + `typing` 空实现 + `forms={"text","image","voice"}`。
- `nonebot/plugins/feishu/__init__.py`：`on_startup` 起长连接；收到事件后立即返回（3 秒内），
  后台任务走 `TurnRunner`（复用会话锁/45 秒硬线/流式分段）。
- 语音：`tts` 加「拿 PCM」出口 → ffmpeg 转 opus → 上传 `file_type=opus` → `msg_type=audio`；
  入站 `audio` 下载 → 16k wav → `asr.transcribe`。
- 命令：复用 `default_registry`（文本命令）；暂不做卡片/按钮。
- 测试：飞书事件 JSON 做离线 fixture；通道无关层继续用 `ops/test-runner.py` 的 FakeChannel。
