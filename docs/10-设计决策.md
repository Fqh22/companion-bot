# 设计决策

> 五份设计稿合一：内核与外包、记忆契约、mood/task、回话自检、语音输入。
> 每节只留结论与判据；过程见 CHANGELOG。

## 一、内核与外包

**判据四问**：影响每一轮？跨轮记住？失败可降级？数据长期滞留？
一句话：**这次调用的结果，要不要影响下一次？** 要 → 内核；不要 → 外包。

| 内核（自己做） | 外包（引外部） |
|---|---|
| 记忆 / 情绪 / 判断 / 节奏 / 人格 / 对话组装 / 调度 / 关系 | ASR / 视觉 / 搜索 / LLM / 嵌入 / TTS / 文件解析 |

边界三项：知识库、任务、表情归内核（带状态）；原料（抓取/解析）可外包。

**代码约定**：外包模块 `web` `asr` `llm` 只允许 `chat` `chat_turn` `memory` `tools` `engine` `group` import；
`lint-layers` 的 `check_outsourced` 会 WARN。

**换掉它还是不是「它」**：ASR/视觉/搜索换掉还是；记忆/情绪/判断换掉不是。

## 二、记忆契约

`MemoryPort` 是契约，不是新库：入口只调 `recall / remember / forget / explain`。

| 类型 | 读 | 写 | 接口 |
|---|---|---|---|
| fact | ✅ | ✅ | MemoryPort |
| knowledge | ✅ | ✅ | MemoryPort |
| profile | ✅ | ✅ | MemoryPort |
| task | ✅ | ✅（followup 创建 / 取消） | MemoryPort |
| mood | ✅ | ✅ | **AffectPort**（状态，不是条目） |

**为什么不塞一起**：`MemoryItem` 是条目语义（可枚举、可删），mood 是单例状态（连续衰减）；
塞进去会让 `recall` 变成「什么都能查」。

**契约宽度 = 实现宽度**：`MEMORY_TYPES` 只声明已实现的类型；未实现的调用显式报错，
不返回空列表（空列表会被当成「没有相关记忆」）。

**迁移是渐进的**：新代码按契约写，存量分步迁；`chat.memory_port=false` 一键回退。

## 三、mood / task

- **task 进 MemoryPort**：状态机 `todo → confirming → done | cancelled | expired`；
  `forget(task)` = 取消，不物理删（要留痕）。
- **mood 走 AffectPort**：`read / observe / write`；影子只能调 `read`（`observe` 有副作用会污染情绪）。

## 四、回话自检

模型在正文前写一行：

```
[自检] 主=接住|判断|事实|执行|轻接 次=同上 置信=高|中|低 | 依据=有|无 来源=记忆|搜索|无
```

代码剥离标签（发送前 + 入库前各一次兜底），写 `data/self_check.jsonl`。
**P1 只观测，不改回复**；标签稳定后再做两段式路由（先出标签 → 决定搜不搜 → 再生成）。

**接住的三条**：状态不明先问；「算了/行吧」可以少回甚至不回；别用「门槛/关键」撑场面。

## 五、语音输入

链路：`record → 下载 → ffmpeg 16k wav → VAD → 智谱 glm-asr-2512 → 场景标注 → 对话`。

**限制**：≤30 秒、≤25MB；超了直接说「没听清」，不截断。

**场景**：人声 → 接话；音乐 → 「这是首歌」，不进对话；静音 → 「没听清」；多人 → 转写不分离。

**隐私**：默认不存原音频，只留文本。

**不做**：说话人分离、听歌识曲、TTS（先保证听得懂）。
