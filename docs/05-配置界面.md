# 配置面板：改 config.yaml 不用再手写 SSH

> 面板属于内核侧（读写 config / 人格 / 关注列表），与通道无关。

> 一个**只绑回环**的本地运维面板。不是公网后台，不进 README 的「不做公网 Web」边界。

---

## 一、它能做什么

- 按分组编辑 `/opt/nonebot/config.yaml`：管理员、模型、总结、向量、工具、上下文、群聊、情绪、表情包、记忆、计费。
- 编辑两份人格（`data/persona.json` / `data/persona-stranger.json`）：system_prompt、示例对话成对校验。
- 编辑巡检话题（`data/watchlist.json`）：最多 8 个，**免重启**；同名话题保留上次的 last 基线。
- 显示每一项的**当前值 / 默认值 / 说明**，标出「已修改」「用默认值」。
- 保存前做类型、范围、枚举校验；非法值不落盘。
- 保存前自动备份，保存后给出 **diff**。
- 保留 YAML 注释、顺序和引号风格（`ruamel.yaml` round-trip），不会把 config.yaml 变成一坨裸 YAML。
- 识别不在 `DEFAULTS` 里的未知键：只展示，原样保留，不会被面板删掉。
- 显示文件修改时间、nonebot 服务状态，以及「配置比服务新，需要重启」。

### 分区：简单项在外面，风险项在里面

顶部四个页签：

| 页签 | 放什么 | 说明 |
|---|---|---|
| **常用** | 14 项：温度、回复长度、思考、情绪阈值、历史预算、媒体等待、影子、图片压缩 | 改了最多影响说话方式/节奏，日常调这里 |
| **高级 / 风险** | 其余 53 项：模型接入、回复模式/上下文、多身份、总结/向量、工具预算、群聊、情绪动力学、记忆清理、计费 | 顶部有警告；15 项标「⚠ 高风险」 |
| **人格** | 两份 persona | 保存后需要 `/reload_persona` |
| **巡检话题** | watchlist | 免重启 |

高风险项（管理员 QQ、API/模型地址、记忆清理、群白名单、画像注入等）在保存前的
diff 弹窗里必须勾选「我了解后果」才能确认——它防误点，不是安全边界（拿到 token 的人仍能改）。

**v2 不做**：一键重启、编辑 `keys.json`、公网访问、通用 JSON 编辑器。

## 二、安装与启动

### 云端（推荐 systemd）

```bash
# 1) 装唯一的新依赖
/opt/nonebot/venv/bin/pip install -r /opt/nonebot/ops/requirements-config-ui.txt

# 2) 部署服务
cp /opt/nonebot/ops/config-ui.service /etc/systemd/system/config-ui.service
systemctl daemon-reload
systemctl enable --now config-ui

# 3) 看 token（只写一次，权限 600）
cat /opt/nonebot/data/config-ui.token
systemctl status config-ui
```

服务只监听 `127.0.0.1:8110`，不会开公网端口。

### 本地临时跑

```bash
pip install -r ops/requirements-config-ui.txt
python ops/config-ui.py --config nonebot/config.example.yaml --port 8110
```

## 三、怎么打开

在你自己的机器上建 SSH 隧道：

```bash
ssh -L 8110:127.0.0.1:8110 root@<server>
```

然后浏览器打开启动日志里的地址：

```
http://127.0.0.1:8110/?token=<token>
```

第一次带 token 访问会种一个 `HttpOnly; SameSite=Strict` 的 cookie，之后地址栏里不会一直挂着 token。

## 四、保存之后

面板只负责写文件，**不负责重启**。

- **config.yaml**：保存后执行 `sudo systemctl restart nonebot`；页面会显示「配置比服务新，需要重启」。
- **人格**：保存后直接在 QQ 发 `/reload_persona`（超管命令，本人/外人两份一起重载）；不重载也不会坏，只是旧人格继续生效。
- **watchlist**：免重启，下一次巡检（周日 20:30）读取新文件。

备份在 `/opt/nonebot/config-backups/`，默认每类保留最近 30 份：
`config-<时间>.yaml`、`persona-owner-<时间>.json`、`persona-stranger-<时间>.json`、`watchlist-<时间>.json`。回滚：

```bash
ls -t /opt/nonebot/config-backups/config-*.yaml | head -3
cp /opt/nonebot/config-backups/config-<时间>.yaml /opt/nonebot/config.yaml
sudo systemctl restart nonebot
```

## 五、安全边界

- 只允许绑定 `127.0.0.1` / `localhost` / `::1`；传别的地址会直接拒绝启动。
- 校验 `Host` 头，防 DNS rebinding；POST 校验 `Origin`，防跨站提交。
- 启动时生成随机 token，写 `data/config-ui.token`（600）；API 也接受 `X-Token`。
- 不执行任意命令、不接收任意路径；配置路径由启动参数固定。
- 不读取 `keys.json`；密钥永远不进浏览器。
- 保存用「同目录临时文件 + `os.replace`」原子替换；写入失败不会留下半截文件。

## 七、已知限制

- 不做「保存并重启」：重启权限和失败回滚是另一套风险，等后续用受限 sudoers + 健康检查再做。
- 未知键只读；如果确实要改，直接编辑文件或加通用 JSON 编辑器。
- 人格示例对话目前是「一行一条」，不支持在界面里可视化角色标签；改角色顺序请谨慎。
- 面板进程挂了不影响机器人；它和 nonebot 是两个独立进程。
