# 语音输入方案

> 目标：把「他发来的语音」变成能接住的话。
> 边界：**做转写与场景判断，不做说话人分离、不做听歌识曲**。

## 一、链路

```
QQ 语音消息（OneBot record）
  → 下载原文件（amr / silk / mp3）
  → ffmpeg 转 16k 单声道 wav（服务器已有）
  → VAD 判断「有没有人声」
  → ASR 转写（云 API 或本地 whisper）
  → 场景标注（人声 / 音乐 / 环境音 / 静音）
  → 文本进 InboundMessage.audio → 正常对话
```

**已定：智谱 GLM-ASR-2512**（`/paas/v4/audio/transcriptions`，multipart，wav/mp3，
**≤30 秒**、≤25MB）。注：方案原写 60 秒，以接口限制为准。

## 二、ASR 选型

| 方案 | 成本 | 延迟 | 隐私 | 准确度 | 适合 |
|---|---|---|---|---|---|
| **云 API**（阿里/腾讯/讯飞/智谱） | 约 0.002–0.01 元/分钟 | 1–3 秒 | 音频出机器 | 高（中文） | 日常 |
| **本地 faster-whisper**（base/small） | 免费 | 10–30 秒/分钟音频（CPU） | 不出机器 | 中（中文尚可） | 隐私/离线 |
| 混合 | 短语音云、长/敏感本地 | — | 折中 | — | 有隐私要求时 |

服务器 3.7G 内存、无 GPU：本地只适合 base 模型、短语音；默认走云 API，配置里留本地开关。

## 三、场景判断（人声 / 音乐 / 环境音）

三层判据，从便宜到贵：

1. **VAD**（静音/噪声）：整段能量极低或无人声 → 「没听到说话」。
2. **ASR 的 no_speech 置信**：whisper 系有 `no_speech_prob`；云 API 多数返回空文本 + 低置信。
3. **文本特征**：输出像歌词/重复短句/带「♪」→ 判「像音乐」，**不转写进对话**。

| 判定 | 回复 |
|---|---|
| 人声，文本清晰 | 正常接话（可标注「你说的是…」） |
| 人声，噪声大/方言 | 转写 + 「可能不太准」 |
| 音乐 | 「这是首歌吧」——不把歌词当他的话 |
| 静音/环境音 | 「没听清，再说一遍？」 |
| 多人 | 转写，**不分离**；文本里可能出现对话片段 |

## 四、失败与兜底

| 失败 | 处理 |
|---|---|
| 格式不支持 / 转码失败 | 「这段我没法转，能不能打字」 |
| 超过 60 秒 | 只转前 60 秒，或提示「太长了」 |
| 下载失败（链接过期） | 同上，不重试超过一次 |
| ASR 超时（>10s） | 降级：不转写，回「没听清」 |
| 识别为空 | 「没听到说话」 |
| 文本超长 | 截 800 字进对话，原文另存 |

## 五、隐私与成本

- **默认不保存原音频**：转写完即删；只留文本（和现有对话一样）。
- 云 API 上传 = 音频出机器：文档里明示，配置提供 `asr.local_only`（true 时只用本地）。
- 成本：每天 10 条 × 30 秒 ≈ 5 分钟 ≈ 几分钱；可忽略，但要有月度用量记录。

## 六、分阶段

| 阶段 | 做什么 | 验收 |
|---|---|---|
| **P0**（1 天） | record 下载 → ffmpeg 转 wav；时长/大小限制；转码失败兜底 | 本地样本 3 种格式能转 |
| **P1**（2 天） | ASR 适配器（云 API）+ 文本进 `InboundMessage.audio` | 真实语音能回话 |
| **P2**（1 天） | VAD + 场景标注（人声/音乐/静音）+ 兜底话术 | 音乐/静音样本不乱回 |
| **P3**（可选） | TTS 语音回复 | 按需 |

## 七、与现有架构的对接

- `InboundMessage` 已有 `audio` 字段；适配层把转写文本放进去，`chat_turn` 不用改。
- `app_core/asr.py`（domain：纯音频处理 + 调用），入口只做下载与发送。
- 配置：`asr.provider`（cloud/local）、`asr.local_only`、`asr.max_seconds`。

## 八、测试与判据

- 离线：mock ASR，测「转码失败/空文本/超长/音乐」四条兜底；
- 真实：人声 10 秒、音乐 10 秒、静音 5 秒、方言 10 秒，各一条；
- 判据：人声转写可用率 > 80%；音乐/静音不误回（判「像音乐/没听清」）；
- 指标：`asr.jsonl`（时长 / 耗时 / 场景 / 是否兜底）。

## 九、不建议现在做的

- **说话人分离**：单人使用，成本高、收益低。
- **听歌识曲**：那是另一个产品，不是「听懂他的话」。
- **语音回复（TTS）**：先保证「听得懂」，再说「怎么回」。
