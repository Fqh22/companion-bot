## 二、部署

```bash
# 本地：先验证
ops/verify.sh --pre

# 备份（云端）
ssh root@<server> '/opt/nonebot/ops/cloud-backup.sh'

# 传代码（adapters 也要带上；companion_core 只有被 bot import 时才必须）
scp -r nonebot/app_core nonebot/adapters nonebot/companion_core nonebot/plugins root@<server>:/opt/nonebot/

# 传脚本（verify.sh 两个名字都认：offline-test.py / test-nonebot-offline.py）
scp ops/link-check.py root@<server>:/opt/nonebot/ops/link-check.py
scp ops/test-nonebot-offline.py root@<server>:/opt/nonebot/ops/offline-test.py

# 云端：权限 + 清缓存 + 重启
ssh root@<server> 'chown -R ubuntu:ubuntu /opt/nonebot/app_core /opt/nonebot/adapters /opt/nonebot/companion_core /opt/nonebot/plugins
                   find /opt/nonebot -name __pycache__ -type d -exec rm -rf {} +
                   /opt/nonebot/ops/verify.sh --pre
                   systemctl restart nonebot
                   /opt/nonebot/ops/verify.sh'
```

**agentd 单独部署**（它不在 /opt/nonebot 下）：

```bash
tar czf /tmp/a.tgz -C agentd agentd     # 注意 -C，路径别多一层
scp /tmp/a.tgz root@<server>:/tmp/
ssh root@<server> 'tar xzf /tmp/a.tgz -C /opt/agentd
                   find /opt/agentd -name __pycache__ -type d -exec rm -rf {} +
                   systemctl restart agentd'
```

### 回滚

`cloud-backup.sh` 每天 03:17 出的 `cloud-<时间>.tgz` 里含 `app_core/plugins`。
**但部署前要另外打一个只含代码的快照**（秒级，回滚最省事，也不用解压 5MB 整机包）：

```bash
tar czf /opt/backup/code-$(date +%Y%m%d-%H%M%S).tgz -C /opt/nonebot app_core plugins

# 回滚
ls -t /opt/backup/code-*.tgz | head -3
tar xzf /opt/backup/code-<时间>.tgz -C /opt/nonebot
find /opt/nonebot -name __pycache__ -type d -exec rm -rf {} +
systemctl restart nonebot
```

## 三、验证（改完必跑）

```bash
ops/verify.sh            # 全量六件套（含 agentd）
ops/verify.sh --pre      # 重启前：分层 + 离线回归 + 联动 + agentd
ops/verify.sh --quick    # 秒级：分层 + 联动
```

| 套件 | 管什么 | 规模 |
|---|---|---|
| 分层检查 | 语法、app_core 不 import nonebot、命令权限门、新模块进体检 | 秒级 |
| 离线回归 | 行为对不对（纯逻辑，全 mock） | 651 项 |
| 联动体检 | **接线**：真 nonebot 跑一遍插件 handler | 47 项 |
| 全链路 | app_core 每个函数至少跑通一次 | 242 项 |
| 插件启动 | 真加载 7 个插件 | 7/7 |
| 真实时钟冒烟 | 不 mock 时间：情绪衰减、字段过期、整分调度 | 7 项（单独跑） |
| agentd | 多步执行/恢复/附件预检/审批/预算（自己的 venv 与 cwd） | 85 项 |

（2026-11-10 本机复跑：651 / 242 / 85；联动 47、插件 7 沿用 11-05 云端数。数字以实跑为准，改测试时顺手更新这一行。）

`ops/smoke-clock.py` 不在六件套里，单独跑：它用真实时钟，专门覆盖「重启 / 时钟跳变 / 任务晚跑」
这些 mock 时间测不到的场景。

agentd 那套以前只写在文档里、要手动跑。**2026-11-05 实证了为什么不能这样**：
planner 里一个未定义变量让 `/task` 的规划整条挂掉，因为在套件之外，上线一天没人发现。
现在它是 `verify.sh` 的第六套；机器上没有 agentd 时显示 SKIP，不会误判成通过。

**想看死代码**：`ops/coverage-audit.py` 列出「零引用」和「只在本文件被调用」的函数（启发式，会误报回调）。

**三条机器守得住的规则**（AST 检查，不靠自觉）：
每个命令必须有权限门；每个新 `app_core` 模块必须出现在 `smoke-all.py` 里；
命令名不得重复（重名时高优先级的 matcher 会把另一个吞掉，用户只会看到其中一个）。

**注意**：`verify.sh` 遇到脚本文件不存在现在直接判 **FAIL**（以前是打印「跳过」并算通过，
等于少跑一套还报绿）。agentd 那套的 SKIP 仍然保留——它可能真的不在同一台机器上。

## 五、备份与恢复

```bash
/opt/nonebot/ops/cloud-backup.sh        # 每天 03:17 自动跑，保留 7 天
```

内容：
- 三个库的一致性导出（`livingmemory.db` / `chat.db` / `agentd.db`）
- `/opt/qqbot-data`（工作区、学习资料、人格、表情包）+ `/opt/nonebot/data`
- 代码 + 配置 + 脚本
- agentd 的 `PLAN.md` / `report.md` / `projects/*/STATE.md`
- 影子日志 `shadow-followup.jsonl` / `shadow-positive.jsonl`（`/opt/nonebot/data` 已在范围内）

**不含**：临时产物、meme_packs 原图、venv。

恢复：`tar xzf /opt/backup/cloud-<时间>.tgz -C /`（先停服务）。

### 异地备份（异地 = 至少离开这块盘）

备份和数据在同一台机器、同一块 40G 盘上：盘挂了或机器没了，备份一起没。
所以每天 03:40 跑 `ops/offsite-backup.sh` 把最新的 `cloud-*.tgz` 推出去。

在 `/opt/nonebot/ops/ops.env`（600，不入库）里三选一：

```bash
# 方式一：任意命令，{file}/{name} 会被替换
BACKUP_PUSH_CMD='rclone copy {file} cos:qqbot-backup/'
BACKUP_PRUNE_CMD='rclone delete cos:qqbot-backup --min-age 30d'   # 可选
# 方式二：装了 rclone
BACKUP_REMOTE=cos:qqbot-backup
# 方式三：装了 coscli
BACKUP_BUCKET=cos://bucket/path
```

状态写在 `ops/offsite.state`：`ok` / `failed` / `unconfigured`。
**未配置不告警**（每 5 分钟响一次没意义），但周报的「运维」段会点名，
`failed` 会被健康检查当成故障。

### 恢复演练（备份能不能用，只有真恢复才知道）

每周日 05:10 跑 `ops/restore-drill.py`：解压最新包 → 每个库 `PRAGMA integrity_check` →
查关键表行数（documents / messages / tasks）→ 抽查代码文件 → 写 `ops/restore.state`。

健康检查在三种情况下告警：上次失败、超过 8 天没跑、从未做过。
手工跑：`ops/restore-drill.py`（`--keep` 保留临时目录排障）。

### 月度维护

每月 1 号 04:50（purge 之后）顺手做三件：影子/矛盾 jsonl 按 30 天截断、
`wal_checkpoint(TRUNCATE)`、`VACUUM`。不做不会坏，但 `prompt_log` 每天删一百多条、
WAL 只涨不落，一年下来是白占的空间。
## 六、看板与状态

### 语气改动怎么验

改人格 / few-shot / 提示词这类「说不清对错」的东西，先跑重放台：

```bash
ops/replay-tone.py 16      # 16 条真实用户消息，每组设置各跑一遍，打表对比
```

它用真实消息、同人格、同提示 → 只改一个变量（比如 thinking 开关），
输出平均字数 / 句数 / 三段比例 / 句长变异。**没有这张表，改语气就是盲调。**

结果写 `/tmp/tone-replay.json`，含每条的完整文本。

```bash
curl 127.0.0.1:8100/health      # agentd 健康 + 今日 token
curl 127.0.0.1:8100/usage       # 按用途拆 token
curl 127.0.0.1:8100/tasks       # 最近任务
```

网页看板（只读、5 秒刷新）：本地 `ssh -L 8100:127.0.0.1:8100 root@<server>`，
然后打开 `http://127.0.0.1:8100/`。

QQ 里：`/tasks` `/progress <号>` `/agent_usage`。

## 七、排障

| 症状 | 先看 | 常见原因 |
|---|---|---|
| 不回复 | `journalctl -u nonebot -n 50` | QQ 掉线 / API 余额 / 配置问题 |
| 回复很慢 | 日志里 `latency` | 思考模式 + 工具轮次；看 `usage` 表 |
| 任务卡住 | `/tasks` + `journalctl -u agentd` | 沙箱起不来 / 等你回答（`needs_input`） |
| agentd 起不来 | `journalctl -u agentd -n 30` | 端口占用 / key 缺失 / 沙箱镜像不在 |
| 沙箱装不了包 | `docker logs agentd-proxy` | 域名不在白名单（看 `DENY` 记录） |
| 记忆没写入 | `/ping` 看配置状态 | `admin.user_id` / `admin.identities` 都没填（服务看着正常但是哑巴） |
| 知识搜不到 | `wiki_pages` 行数 | 索引挂了（embedding 批量超限会静默失败） |
| 群聊不回 | `group.enabled` / `whitelist` | 默认关闭，白名单空 = 全不回 |

### 常用排查命令

```bash
# 昨天哪个定时任务没跑
sqlite3 /opt/nonebot/data/chat.db "select * from job_runs order by ts desc limit 10"

# 记忆库状态
sqlite3 /opt/qqbot-data/livingmemory.db "select count(*) from documents"

# 索引是否落后
sqlite3 /opt/nonebot/data/chat.db "select count(*) from wiki_pages"

# 今天花了多少
sqlite3 /opt/nonebot/data/chat.db \
  "select purpose, sum(prompt_tokens+completion_tokens) from usage
   where ts > strftime('%s','now','-1 day') group by purpose"
```

## 八、安全清单

| 项 | 现状 |
|---|---|
| 命令权限 | 全部 `permission=SUPERUSER`；AST 检查保证 |
| 密钥 | `/opt/qqbot-data/keys.json`（600），不进仓库 |
| agentd 监听 | 只绑 127.0.0.1，靠 SSH 隧道访问 |
| 沙箱 | 只读 rootfs、cap-drop、只挂 `/work`、无凭证 |
| 沙箱出网 | 内网 + 白名单代理；iptables 禁止直连宿主网关 |
| OOM 保护 | QQ 容器 `oom_score_adj=-500`，沙箱 `+500` |
| 备份 | 每天 03:17；`cloud-*.tgz` 保留 7 天；部署前的 `code-*.tgz` 手动轮转 |
