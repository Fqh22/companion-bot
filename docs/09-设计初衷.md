# 设计初衷

> 这份文档是项目的**最高准绳**。任何新增能力、重构、取舍，先对照这里；
> 与它冲突的，不做。

## 定义

**它不是聊天机器人，而是一个长期记忆体。**

对话、命令、定时任务、主动消息都是它的**读写端口**；记忆是唯一的**主链路**。
对话是它的一种呈现，不是它的本体。

## 三个不变量

1. **记忆是契约，不是容器。**
   所有能力通过 `recall / remember / forget` 读写，不直接碰存储；
   但不同记忆类型（事实 / 画像 / 知识 / 情绪 / 任务）各有生命周期，不塞进一个库。

2. **对话是端口，不是中心。**
   它和命令、定时、主动消息平级。判断一个功能是否属于这个系统，看它读写了什么记忆，
   而不是看它是不是"聊天的一部分"。

3. **似人，但不是人。**
   表达像人：有情绪、有停顿、会主动。
   记忆不像人：不失真、不遗忘（除非策略要求）、不记仇、不因情绪改变事实。
   两层不互相污染。

## 决策判据

加任何东西之前，回答四个问题：

1. **它读什么记忆、写什么记忆？** 答不上来，就不加。
2. **它写的是「跨会话仍然成立的断言」吗？** 不是，就只进日志，不进记忆。
3. **它会让记忆层变成万能层吗？** 会（塞对话历史、临时状态、配置、日志），就拒绝。
4. **它会让表达污染事实吗？** 会（情绪改变记忆、语气改写结论），就拆开。

## 现状与差距

| 维度 | 现在 | 目标 |
|---|---|---|
| 主链路 | 对话（`chat_turn` 直接调 memory / profile / wiki） | 记忆（入口只调记忆契约） |
| 记忆形态 | 各子系统各有存储（SQLite / JSON / Markdown） | 统一契约，按类型分层 |
| 写入时机 | 主要是总结时 | 每次交互按判据写 |
| 可解释性 | 靠日志 | 每条回复可追溯读了哪些记忆 |

**迁移是渐进的**：新代码按契约写，存量代码分步迁。
不为"纯粹"重写——上一次为架构而重写（agentd）的代价已经验证过。

## 不做什么

- **不做通用助手**：任务执行、多步规划不在主链路里；最多是"会写记忆的工具"。
- **不做多用户**：记忆是"关于一个人"的，多租户会稀释前提。
- **不做无记忆的对话**：一次交互不读也不写记忆，就不属于这个系统。
- **不追求"像人"的缺陷**：会忘、会错、会情绪化伤人，不在设计目标里。

## 对外表达

先给体验，再给结构：

> 它记得住你——不是记住这一轮，是记住这几个月。
> 对话只是它的一种呈现。
