# 设计初衷

> 最高准绳。与它冲突的，不做。

## 定义

**它不是聊天机器人，而是一个长期记忆体。**
对话、命令、定时、主动消息都是读写端口；记忆是唯一主链路。

## 纲领：接住

> **让「说过的话」有去处——被听见、被记住、被恰当地回应，而且一直如此。**

对话是端口，记忆是本体，但**接住是它们共同的目的**。

它不是一个模块，是整套系统的体感：记忆是前提、情绪是语气、自检是判断、日记是底气、
pacing 是剂量、不记仇不表演是信用。任何单个零件都不是它，零件的合力才是。

判据（每条回复问一遍）：

1. **听见了吗**——回复里有没有他这句的具体内容，而不是通用回应。
2. **有去处吗**——这轮产生的东西（事实/状态/待办）有没有进记忆。
3. **剂量对吗**——长度、语气、追问次数，配不配得上他这句的分量。

**反面是「接得太用力」**：每句都追问是黏，每句都共情是表演，每句都分析是上课。
真正的接住包含「不接」——他说「算了」就不追问，说「行吧」就不分析。

## 三个不变量

1. **记忆是契约，不是容器。** 能力通过 `recall / remember / forget` 读写。
   契约只声明**已实现**的类型（事实 / 画像 / 知识）；情绪 / 任务未实现，调用会显式报错，
   不返回空列表——缺口必须无声可查。
2. **对话是端口，不是中心。** 判断一个功能是否属于这个系统，看它读写什么记忆。
3. **似人，但不是人。** 表达像人；记忆不失真、不遗忘、不记仇。

## 决策判据

1. 它读什么记忆、写什么记忆？答不上来，不加。
2. 写的是「跨会话仍成立的断言」吗？不是，只进日志。
3. 会让记忆层变成万能层吗？会，拒绝。
4. 会让表达污染事实吗？会，拆开。

## 现状与差距

| 维度 | 现在 | 目标 |
|---|---|---|
| 主链路 | 对话 | 记忆 |
| 记忆形态 | 各子系统各有存储 | 统一契约，按类型分层 |
| 写入时机 | 主要是总结时 | 按判据写 |
| 可解释性 | 靠日志 | 可追溯读了哪些记忆 |
| 契约覆盖 | fact / profile / knowledge / task 读写 + mood 走 AffectPort（5/5） | 五类各自进出契约 |

迁移渐进：新代码按契约写，存量分步迁，不为纯粹重写。

## 不做什么

- 通用助手：任务执行、多步规划不在主链路
- 多用户
- 无记忆的对话
- 「像人」的缺陷：会忘、会错、会情绪化伤人

## 对外表达

> 它记得住你——不是记住这一轮，是记住这几个月。
> 对话只是它的一种呈现。
