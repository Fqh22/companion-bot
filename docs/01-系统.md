# 系统：消息进来后发生什么

> 本文描述**聊天内核**的内部机制（与平台无关）；通道接入见 [06-移植](06-移植指南.md)，
> 部署排障见 [02-运维](02-运维.md)。

---

## 一、全局图

```
QQ ── SnowLuma（容器，OneBot v11）
        │ ws://127.0.0.1:3001
        ▼
   NoneBot（adapters 只做 IO，app_core 是纯逻辑）
        ├─ chat     私聊：聚合 → Engine.handle → ChatCore.reply → 发送
        ├─ group    群聊：独立链路，无记忆无情绪
        └─ commands / admin / schedule / proactive
        │
        ├─ chat.db（消息/用量/纪要/情绪/知识索引/identity_map）
        └─ livingmemory.db（记忆原子 + 向量）
```

**入口是 Engine**：QQ/console 都构造 InboundMessage，Engine 再调 ChatCore.reply。
ChatCore 是当前实现，不是唯一实现；插件之间不互相调用。

## 二、私聊链路

```
收到消息
 1. 聚合（app_core/turn.py + plugins/chat 的泵）
      · 文本零等待；图片/文件最多等 1.5 秒，看他有没有补一句
      · 生成期间来的消息排队，当前轮结束立刻处理
 2. 会话锁：同一会话串行，不并发打乱历史
 3. Engine.handle → ChatCore.reply()
      · 情绪 settle（按流逝时间衰减）→ observe → save
      · 读历史（**先读后写**，否则当前这句在 prompt 里出现两次）
      · 召回：记忆 5 条 + 知识 3 条 + 技能 + 纠正
      · 拼 prompt：稳定前缀 + 历史 + 背景/情绪 + 尾部锚点
      · 调模型（可挂工具，最多 6 轮）
      · 写库
 4. 发送：按情绪 18–32 字切段（DeliveryPolicy 可覆盖），按情绪给间隔，边生成边发
```

**45 秒硬线**：`reply_deadline_seconds`。超时就补发已生成的部分。

### prompt 的顺序（别乱动）

```
稳定前缀（缓存友好）：人格 → 防注入规则 → 怎么回指南/例子 → 画像 → 纪要
易变：历史 → 情绪 → 【背景】（compact：记忆/笔记/技能/纠正/待办） → 尾部锚点 → 本轮输入
```

记忆/笔记/情绪**每轮都变**，所以放在历史之后；默认 `context_format=compact` 会合成一个【背景】块。
旧的分块注入保留为 `legacy`，两者可切换。

### 「这一轮怎么说」是**一段**，不是五段（仅 rules 模式）

默认 `style_mode=model`：跳过 `style_block`，由人格 + 尾部锚点决定怎么说。
切到 `style_mode=rules` 时才启用下面的合成规则；长度 / 形式 / 图片 / 时效 / 时间
由 `prompt.style_block()` 合成一条（以前五条会互相打架，`allow_short` 就是补丁）。

优先级（后面的让位前面的）：

```
图片求助  >  允许展开  >  形式约束  >  说短点  >  时效
```

- 求助类图片**不压长度**（图文都可能带信息）
- 纯情绪短句、只发一张图 → **省掉时效规则**（省约 60 token/轮）
- 形式里的「说短点」在允许展开时自动消失
- 纠正清单仍是独立一段（参考材料，不是说话方式）

### 语气：模型优先，规则兜底

**1. 思考常开**（`llm.thinking_casual`，默认 false）

2026-11-10 A/B（10 条真实消息）：开思考在事实类问题上更准（不编数字，如「制程」题），
平均字数几乎无差（35 vs 38），代价是首字慢约 0.8 秒。用户决定常开。

分流逻辑仍保留在 `_thinking_for` 里：把 `llm.thinking_casual` 改回 true，
就恢复「短句、无问号、无技术词、不带图 → 关」的策略（重放实测句数 2.3 → 1.2）。

**2. 结尾建议按情况处理（rules 模式）**

model 模式不剪建议，交给人格和尾部锚点；`strip_advice_tail` 只属于 rules。

- 他在征求意见（该不该/要不要/怎么办/选哪个/你觉得）→ **不剪**，
  提示词反而要求「明确给倾向，别打太极」
- 他在问事实 → 剪掉结尾那句说教
- 流式时先把疑似建议句**扣住**，下一句到了说明不是结尾再补发

判据只认第二人称劝告句式。**「可以并发读」不算建议**——那是事实句。

**3. 影子模式**（`app_core/shadow.py`，只记不发）

- `data/shadow-followup.jsonl`：抽 30% 生成一句「本来可以补的话」
- `data/shadow-positive.jsonl`：他说「哈哈/笑死/懂了」时记一条正例
- `data/shadow-retrieval.jsonl`：召回算两遍——dense 一遍、BM25+RRF（`app_core/retrieval.py`）
  一遍，记两路各自的 top-5 与重合数。**返回值仍按 dense 算**，
  这批样本用来判断关键词通道要不要转正；`memory.shadow_retrieval` 可关。
- `data/shadow-graph.jsonl`：召回后按共同实体找邻居，记新增候选。
  2026-11-10 快照：333 次里 99% 有邻居、平均新增 5 条——**这是覆盖率，不是精度**，
  仍在抽检，不能据此转正。
- `data/shadow-profile.jsonl` / `shadow-second.jsonl` / `shadow-attention.jsonl`：
  画像块、二次召回命中、自指率；同样只记不发。

用来在真改行为前先量收益。**正例闭环之前完全没有**——只吃负例，正例全丢。

**4. 轻浮语气词会被拿掉（rules 模式）**

model 模式不再用 `soften_tone` 删词，交给人格/例子；只有 rules 模式执行下面的替换。
「哈哈/笑死/好家伙/啊这/emmm」这类词一出现就把整句带偏，`prompt.soften_tone()`
在发出前删掉它们并收拾标点（「不用睡，充电算吗，哈哈哈」→「不用睡，充电算吗」）。
整条回复只有语气词时给最中性的一句，不发空消息。

配套：人格明确「别贫——不抖机灵、不油腔滑调、不为显得有趣而跑题」。

### 别人来聊时（私聊隔离）

别人也能私聊它，但**读不到也写不进**他的东西。判据是 `admin.user_id` 或
`admin.identities` 经 `identity_map` 映射后的内部 ID；QQ 的存量 key 不变。
**两套都没配时判据失效**：所有人都会被当成本人（fail-open，否则一上线全哑），
所以部署第一步必须填号；启动日志和 `/ping` 会报警。

| 项 | 本人 | 别人 |
|---|---|---|
| 人格 | 主人那份（写满「我和他」） | `data/persona-stranger.json`，缺文件用内置兜底 |
| 记忆 / 知识 / 纠正 / 画像 / 未跟进事项 | 全注入 | **都不注入** |
| 情绪 | 观察并保存 | 不 observe、不保存（情绪是全局单例，别人能带跑他的心情） |
| 工具 | 全部 | 只有 `web_search` / `meme_send` |
| 影子样本 | 记 | 不记（陌生人的话不进调参基线） |
| 深夜 | 照常回 | 0–8 点静默（在插件入口判断，prompt 里写「不回复」拦不住发送） |

**为什么人格必须分两份**：主人那份写着关系、称呼、共同经历，念给陌生人听等于泄底。
所以外人版**绝不回落到**主人那份——文件丢了就用内置的最小人格。

**工具的判据不是读写，是「碰不碰他的库」**：`web_search` 只出网，
`meme_send` 只发图，都不读记忆、不写文件，所以放行；其余一律禁。
`web_open` 曾经也在名单里，后来移除了——它会把提炼结果 `note_write` 进知识库
（`app_core/web.py`），是写入口，不是纯出网。

## 三、图片

- 压缩：长边 1600、JPEG q90、纠 EXIF 方向
- 默认 model 模式只给中性提示：自己判断是分享、表情还是求助；分享先接情绪，不描述画面
- rules 模式才注入「图文比对 + 强度分级」：先判断图/文字/一致矛盾，再决定 L1–L3 回应强度
- **图注后台补**：回复发出后异步生成一句图注追加到那条用户消息，下一轮历史就能看到图里是什么

## 四、群聊（独立链路，默认关闭）

```
@机器人 → GroupCore
  · 只认 @，20 条进程内上下文（重启即忘）
  · 无记忆、无情绪、无工具、无知识
  · 限流：3 条/分钟、5 秒冷却、每日 5 万 token
  · 失败静默，不刷屏
```

`whitelist` 为空 = 任何群都不回。**隐私边界**：群消息不会进记忆库，prompt 里也没有
「他喜欢什么」这类内容。

## 五、主动消息

```
定时器 → proactive.gate（该不该开口：情绪/精力/静默时长/每日上限）
       → 挑话题（提醒到期 / 跟进 / 日记回访 / 好奇清单）
       → 发送 → 写回历史
```

判断是纯函数（可测），发送在插件。

## 六、记忆闭环

```
对话 ──(30 分钟空闲 / 攒够量)──> summarize ──> 结构化 JSON
                                              ├─ memory.add_document（事实/偏好/事件）
                                              ├─ followup.add（要做的事）
                                              └─ session_digest（纪要）
记忆 ──(每轮)──> recall（时间加权 + 向量）──> prompt
     └─(被用到)──> use_count++ ──(长期)──> cleanup 分层保留
```

**两道幂等**：`range_key` 管「同一段对话只固化一次」；同文本去重管
「同一段文字 10 分钟内不写第二条」（`memory.dup_window_minutes`，设 0 关闭）。
后者是为老记忆准备的——加 range 之前写的那批没有 range_key。

清理分层：importance ≥0.8 半年、0.5–0.8 三个月、<0.5 一个月。**只归档不删除**。
`learn/raw/`（原文归档）永不清理。

**矛盾检测**：新记忆写入时，若和某条活跃旧记忆余弦 ≥0.5，问一次模型
「是不是同一件事的两个版本」；是就把旧的标成 `superseded`（软删）。
四道闸：≥0.6 才改、必须给理由、每次最多 2 条、每条决定落 `data/contradictions.jsonl`。
`/memory_conflicts` 看判了什么，判错了 `/memory_restore 关键词` 捞回来。

## 七、知识闭环与时效

```
模型写笔记（note_write 自带「保质期：N 天」）
  → learn/notes/*.md
  → 每小时索引：wiki_pages（标题+摘要，注入 prompt 的目录）
                kb_chunks（切块+向量，给 kb_search）
  → 过期：索引标【可能过时】→ 正文顶部提示
  → 周日周检 → 无人读 + 已过期 + 未验证 → 状态改「已废弃」（最多 5 页）
  → 每月 1 号 → 打包备份 → 删文件 → 删库行（三条件全满足，最多 20 页）
```

**边界**：知识库可以清；记忆库和 `learn/raw/` 不碰。

### 时效四层（防「知识截止」）

| 层 | 做法 |
|---|---|
| L1 | prompt 里写死**自主搜索**规则：涉及事实、价格、权限、"现在"就先搜，不看关键词表 |
| L2 | 回答带日期（"截至 2026-11"），让过时自己暴露 |
| L3 | 写笔记时由模型判保质期（价格 14 天 / 版本 30 天 / 方法论永久） |
| L4 | 每周日 20:30 巡检固定话题（`watchlist.json`），**只报真的变了** |

## 八、情绪

三值（心情 / 基线 / 精力）+ 惰性衰减，不是计数器。

- 衰减用耦合线性方程解析解，`τv=5h`、`τb=72h`、`τe=8h`
- 冲量带饱和（越接近边界越推不动）
- 事件化：超时、工具失败、被纠正、重逢都会动情绪
- 每天 23:55 存一行 `mood_history`（保留 400 天），为调参留数据
- 下游用**相对基线**的阈值，不用绝对值（换动力学后绝对值会静默失效）

## 十、配置速查

完整键见 `nonebot/config.example.yaml`（带注释）。最常调的：

| 键 | 默认 | 说明 |
|---|---|---|
| `llm.temperature` | 1.15 | 思考模式不生效，保留是为了切回非思考 |
| `llm.max_tokens` | 1000 | 单条回复上限 |
| `llm.reply_deadline_seconds` | 45 | 硬线，超时补发已生成部分 |
| `llm.thinking_casual` | false | 默认常开思考；true 时恢复「闲聊短句关思考」的分流 |
| `llm.max_tool_rounds` | 6 | 每多一轮 ≈ +1.5 秒 |
| `context.history_max_chars` | 2500 | 没有纪要时自动放宽到 4000 |
| `context.summary_idle_minutes` | 30 | 空闲这么久也触发总结 |
| `chat.media_settle_seconds` | 1.5 | 图片/文件后等他补一句 |
| `chat.shadow_followup` / `shadow_sample` | true / 0.3 | 影子记录（只记不发） |
| `chat.style_mode` | model | model = 只给人格/例子；rules = 旧的长度/形式/剪建议 |
| `chat.context_format` | compact | compact = 单【背景】块；legacy = 旧分块注入 |
| `admin.identities` | [] | 多入口管理员；QQ 仍可用 user_id |
| `image.max_side` / `quality` | 1600 / 90 | 图片压缩 |
| `meme.threshold_*` | 0.12/0.16/0.08 | 表情包三档，按情绪分 |
| `memory.cleanup_days_*` | 180/90/30 | 分层保留 |
| `group.*` | 关闭 | 群聊独立链路 |
| `watch.topics` | 空 | 只在 watchlist.json 不存在时写入 |
| `memory.dup_window_minutes` | 10 | 同文本多少分钟内不重复写；0 = 关闭 |
| `memory.contradiction_check` | on | `off` / `shadow`（只记）/ `on`：新记忆是否标记推翻旧记忆 |
| `profile.inject` | shadow | `off` / `shadow`（只落盘）/ `on`（真注入，仅本人）；120 天没新证据的字段自动作废 |

**改完要重启**（`config.load()` 是进程内缓存）。人格和 `watchlist.json` 不用重启。

## 十二、容易踩的坑（都踩过）

1. **先写库再读历史** → 当前消息在 prompt 里出现两次
2. **调度用 `if now.weekday()==6`** → 周日停服就整周丢；要按「目标日期是不是周日」
3. **换动力学后不重标定阈值** → 绝对阈值变死代码（`valence<-0.3` 永远到不了）
4. **`merge_list` 静默截断** → 最老的条目被悄悄丢掉
5. **`on_command` 默认连群聊一起匹配** → 群里任何人都能敲 `/usage`
6. **重试路径漏传参数** → 白名单/开关变回默认值（外人那次就拿回了全部工具）
7. **历史写「模型生成的」而不是「用户收到的」** → 它以为自己说过，下一轮说「我上面不是说了」
8. **发送成功前就记「已完成」** → 发失败也不会重试，用户永远等不到，日志里一切正常
