# 项目概览

companion-bot 是一个自托管的 QQ 陪伴机器人，提供长期记忆、情绪状态，以及一个可执行多步任务的沙箱 agent。项目自 2026-10-31 起在单用户环境下持续运行。

仓库：https://github.com/Fqh22/companion-bot

## 一、背景与定位

现有聊天机器人在长期使用中普遍存在三项不足：记忆随会话结束而丢失；回复缺少情绪与节奏变化；无法承担需要多步执行的任务。

本项目在同一套代码中实现两条独立链路：陪伴聊天（记忆、情绪、主动消息）与任务 agent（沙箱内多步执行、崩溃可恢复）。两条链路共享存储层，但不共享上下文。

范围之外的功能明确不予实现：多用户、群聊默认关闭、公网 Web 界面、多 agent 并行。相关约束记录于 README 的「边界（不做的事）」，用于控制范围蔓延。

## 二、使用场景

单用户，以私聊为主。典型交互包括日常对话、情绪表达、信息记录，以及通过 /task 提交需要多步执行的任务。

## 三、关键设计决策

| 决策 | 备选方案与代价 | 依据 |
|---|---|---|
| 记忆内容置于历史之后，画像作为稳定前缀 | 置于之前更符合阅读直觉，但每轮前缀随之变化，缓存全部失效 | 实测缓存命中率 44.9%，直接影响调用成本 |
| 表情包触发阈值按情绪分三档（0.12 / 0.16 / 0.08） | 单一阈值实现简单，但负向词表覆盖不足，负面情绪下无法触发 | 正向表达 3 句可达 0.28，负向同等句数仅 -0.20 |
| 表情包发送采用 base64 编码，并在发送前压缩至长边 800 | 直接传递文件路径实现最简单，但 OneBot 运行于容器内，无法访问宿主机路径（ENOENT） | 单张 926KB 压缩至 86KB 后实测送达；图库中 109/180 张超过 300KB |
| 关键词检索（BM25+RRF）先以影子模式运行，不改变召回结果 | 直接上线无法量化收益与风险 | 设定判据：运行 14 天且样本 ≥50；平均重合 ≥4.0 则停用，≤3.0 则启用；截止 2026-11-19 |
| 将 reply() 由 356 行拆分为四段流水线 | 不拆分亦可运行，但任意修改都需通读全文 | 纯代码移动，行为不变，由 651 条离线用例保障 |
| 插件仅允许调用 CORE_API 清单内的成员 | 自由调用更灵活，但内部结构会被外部固定 | 由 lint 强制校验，未登记的调用直接失败 |
| QQ 适配器与引擎用 Engine/InboundMessage 隔离，console 作为第二入口 | 直接调 ChatCore 更快，但换入口要重写 | M1/M2 已上线，M0 结构重放 22/22 |
| 身份用 identity_map 映射，QQ 存量 key 不改 | 直接改所有表最彻底，但迁移成本和风险高 | M3 已上线，QQ 数据零迁移 |
| 回复默认 model-first + compact 注入 | 继续加规则更可控，但 prompt 会越来越碎 | style_mode/context_format 可一键回退 |
| 先做 companion_core 门面，不物理搬包 | 直接搬约 45 个模块最彻底，但风险和成本高 | M6-mini；等第二个消费者再做 M6-full |

上述决策的代价均记录在文档中：分档阈值后续需重新标定；流水线拆分增加一层间接；接口清单新增成员需登记。

## 四、质量保障

项目以六套验证替代人工确认。CI 在每次推送时执行分层/密钥扫描 + 离线/全链路/agentd，
以及 kernel、Engine、适配器、身份、投递、审批、包门面等专项测试；
联动与插件启动需要完整运行环境，由本地 `ops/verify.sh` 覆盖：

| 套件 | 数量 | 覆盖范围 |
|---|---|---|
| 分层与规范 | — | 核心层不依赖框架、命令不重名、路径不硬编码、接口不越界 |
| 离线回归 | 651 | 行为正确性（不联网、不读写生产库） |
| 联动体检 | 47 | 插件与核心层之间的调用契约 |
| 全链路 | 241 | 全部模块与端到端流程 |
| 插件启动 | 7 | 7 个插件的真实加载 |
| agentd 单测 | 81 | agent 循环、沙箱与审批流程 |

> 另有 engine 7、identity 6、delivery 25、approval 10、console 7、console e2e 9、
> 入站 6、包门面 5、kernel 7；M0 结构重放 22（需要本地 fixture）。

## 六、风险与限制

| 风险 | 应对措施 |
|---|---|
| QQ 未提供个人号官方接口，依赖第三方 OneBot 实现 | README 明确说明可能中断及迁移方式；健康检查每 5 分钟探测登录状态 |
| 单用户环境，无外部用户数据 | 不以用户量作为指标，以实际运行数据说明使用强度 |
| 记忆效果缺少量化评估 | 影子模式采样、周报指标、判据与截止日期 |
| 账号存在风控风险 | 建议使用独立账号；该风险无法通过代码规避 |

## 七、设计原则

1. 决策需附带数据：每项取舍记录备选方案、依据与代价，变更日志按日期归档。
2. 影子模式必须设定截止时间：仅采样不改变行为的实验，到期须转为正式逻辑或移除。
3. 约定由工具强制执行：分层约束与接口清单均实现为自动检查，不依赖人工遵守。
4. 优先处理静默失败：不报错但导致效果下降的问题（如路径失效、依赖缺失）应优先补充可观测性。
