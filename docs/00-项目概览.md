# 项目概览

companion 是一个自托管的**聊天内核**：提供长期记忆与情绪状态，
平台（QQ、终端、将来的其他入口）只是接入层。项目自 2026-10-31 起在单用户环境下持续运行。

仓库：https://github.com/Fqh22/companion-bot

## 一、定位

聊天机器人的两个常见缺陷：记忆随会话结束而丢失；回复缺少情绪与节奏。
本内核把记忆、情绪、主动消息、知识库放在同一条链路里，并把平台隔离在适配层。

范围之外：多用户、群聊默认关闭、公网界面、多 agent 并行、多步任务执行。

## 二、分层

内核按职责分三层，由 `ops/lint-layers.py` 强制（详见 [07-分层.md](07-分层.md)）：

| 层 | 职责 | 例子 |
|---|---|---|
| domain | 纯规则，不碰 IO | `prompt` `pacing` `delivery` `intent` |
| orchestration | 一轮对话、命令、调度 | `engine` `runner` `commands` `runtime` `chat` |
| infra | 路径、配置、文件、时钟 | `paths` `config` `files` `kernel/*` |

平台侧只有两类东西：`adapters/`（字段归一化 + 三个原语）与 `plugins/`（NoneBot 胶水）。

## 三、关键设计决策

| 决策 | 备选与代价 | 依据 |
|---|---|---|
| 通道抽象为三个原语（发文本 / 发图 / typing） | 直接调平台 SDK 更快，但每个通道都要重写会话循环 | 会话循环已抽到 `app_core/runner.py`；QQ 与 console 两个实现 |
| domain 不得依赖 orchestration | 自由 import 更省事，但纯规则会绑上会话状态 | lint 强制；反向验证过（加一行坏 import 立即 FAIL） |
| 记忆置于历史之后，画像作为稳定前缀 | 置于之前更符合阅读直觉，但每轮前缀变化会让缓存失效 | 实测缓存命中率 44.9% |
| 表情包阈值按情绪分三档（0.12 / 0.16 / 0.08） | 单一阈值简单，但负向词覆盖不足时无法触发 | 正向 3 句可达 0.28，负向同等句数仅 -0.20 |
| 表情包以 base64 发送并压到长边 800 | 传路径最简单，但 OneBot 在容器内看不到宿主路径（ENOENT） | 926KB → 86KB 后送达；图库 109/180 张超 300KB |
| BM25 检索先影子、不改召回 | 直接上线无法量化收益 | 判据：14 天且样本 ≥50；平均重合 ≥4.0 停用、≤3.0 启用；截止 2026-11-19 |
| reply() 拆为四段流水线 | 不拆也能跑，但每次修改都要通读全文 | 纯移动，由离线用例保障 |
| 插件只调 CORE_API 清单成员 | 自由调用更灵活，但内部结构会被外部固定 | lint 校验，未登记即失败 |
| 回复默认 model-first + 信号包 | 继续加规则更可控，但 prompt 会越来越碎 | `style_mode` / `context_format` 可一键回退 |

## 四、质量保障

以自动验证替代人工确认。CI 在每次推送时执行分层、密钥扫描、离线回归、全链路、
通道无关层、命令层等专项；联动与插件启动需要完整运行环境，由 `ops/verify.sh` 覆盖：

| 套件 | 数量 | 覆盖范围 |
|---|---|---|
| 分层与规范 | — | 核心层不依赖框架、domain 不反向依赖、适配层不越界 |
| 离线回归 | 647 | 行为正确性（不联网、不读写生产库） |
| 联动体检 | 43 | 插件与核心层之间的调用契约 |
| 全链路 | 239 | 全部模块与端到端流程 |
| 通道无关层 | 7 | 流式顺序、typing、超时、补发 |
| 命令层 | 11 | 解析、权限、默认注册表 |
| 插件启动 | 6 | 6 个插件的真实加载 |

> 另有 engine 7、identity 6、delivery 25、approval 10、console 7、console e2e 9、
> 入站 6、包门面 5、kernel 7、面板 48。

## 六、风险与限制

| 风险 | 应对 |
|---|---|
| QQ 无个人号官方接口，依赖第三方 OneBot 实现 | 平台隔离在最外层；健康检查每 5 分钟探测登录；文档记录迁移路径 |
| 账号风控 | 建议独立账号；无法通过代码规避 |
| 单用户环境 | 不以用户量作指标，以运行数据说明使用强度 |
| 记忆效果缺量化 | 影子采样、周报指标、判据与截止日期 |

## 七、设计原则

1. **决策附带数据**：每项取舍记录备选、依据与代价。
2. **影子实验必须有截止时间**：到期转正或移除。
3. **约定由工具强制**：分层、接口等约束实现为自动检查。
4. **优先处理静默失败**：不报错但让效果变差的问题，优先补可观测性。
