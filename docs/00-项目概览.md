# 项目概览

companion 是一个自托管、可携带的**持续陪伴主体**：记得住你说过什么，更知道什么时候不该提、
怎么说才不冒犯，并能在授权下把小事办完。通道、模型、记忆引擎都是可换的零件。
项目自 2026-10-31 起在单用户环境下持续运行。现行定义见 [22-项目定义](22-项目定义.md)；
历史定义（记忆体 / 接住）见 [09-设计初衷](09-设计初衷.md)。

仓库：https://github.com/Fqh22/companion-bot · 文档地图：[docs/README.md](README.md)

## 一、定位

聊天机器人的两个常见缺陷：记忆随会话结束而丢失；回复缺少情绪与节奏。
本内核把记忆、情绪、主动消息、知识库放在同一条链路里，并把平台隔离在适配层。

现行定义与五条决策判据见 [22-项目定义](22-项目定义.md)：**判断/克制是第一支柱，记忆是被调用的资源**。
历史沿革见 [09-设计初衷](09-设计初衷.md)；迁移路径见 [10-设计决策](10-设计决策.md)。

设计理念是「**似人，但不是人**」：保留情绪与连续性，不接受静默遗忘与失真的缺陷。
事实要求精确、可溯源、矛盾可裁决；表达要求口语、有停顿、懂克制。两层不互相污染。

范围之外：多租户、公网界面、无人监督的自主规划与不可逆执行、插件市场。
**可授权的短任务在范围内**（副作用可追溯、可回滚，见 [22-项目定义](22-项目定义.md) 的「可授权性」）。

## 二、分层

内核按职责分三层，由 `ops/lint-layers.py` 强制（详见 [06-扩展与移植.md](06-扩展与移植.md)）：

| 层 | 职责 | 例子 |
|---|---|---|
| domain | 纯规则，不碰 IO | `prompt` `pacing` `delivery` `intent` |
| orchestration | 一轮对话、命令、调度 | `engine` `runner` `commands` `runtime` `chat` |
| infra | 路径、配置、文件、时钟 | `paths` `config` `files` `kernel/*` |

加东西的五条路径见 [06-扩展与移植.md](06-扩展与移植.md)。

平台侧只有两类东西：`adapters/`（字段归一化 + 三个原语）与 `plugins/`（宿主胶水）。
当前通道：QQ（OneBot v11，第三方协议，有风险）、飞书（自建应用 + 长连接，官方）、终端（调试）。
个人微信不支持。

## 三、关键设计决策

| 决策 | 备选与代价 | 依据 |
|---|---|---|
| 通道抽象为三个原语（发文本 / 发图 / typing） | 直接调平台 SDK 更快，但每个通道都要重写会话循环 | 会话循环已抽到 `app_core/runner.py`；QQ 与 console 两个实现 |
| domain 不得依赖 orchestration | 自由 import 更省事，但纯规则会绑上会话状态 | lint 强制；反向验证过（加一行坏 import 立即 FAIL） |
| 记忆置于历史之后，画像作为稳定前缀 | 置于之前更符合阅读直觉，但每轮前缀变化会让缓存失效 | 实测缓存命中率 44.9% |
| 表情包阈值按情绪分三档（0.12 / 0.16 / 0.08） | 单一阈值简单，但负向词覆盖不足时无法触发 | 正向 3 句可达 0.28，负向同等句数仅 -0.20 |
| 表情包以 base64 发送并压到长边 800 | 传路径最简单，但 OneBot 在容器内看不到宿主路径（ENOENT） | 926KB → 86KB 后送达；图库 109/180 张超 300KB |
| BM25 检索先影子、不改召回 | 直接上线无法量化收益 | 判据：14 天且样本 ≥50；平均重合 ≥4.0 停用、≤3.0 启用；截止 2026-11-19 |
| reply() 拆为四段流水线 | 不拆也能跑，但每次修改都要通读全文 | 纯移动，由离线用例保障 |
| 插件只调 CORE_API 清单成员 | 自由调用更灵活，但内部结构会被外部固定 | lint 校验，未登记即失败 |
| 回复默认 model-first + 信号包 | 继续加规则更可控，但 prompt 会越来越碎 | `style_mode` / `context_format` 可一键回退 |
| **2026-11-16 重定义：判断/克制为第一支柱，主体可携带、可授权（A+B+C）** | 沿用「记忆是本体」可继续自研，但会与 AstrBot / Mem0 / Zep / memU 正面比可替换零件 | RealCompanion：真实陪伴流量仅 3.4% 消息需回忆、池化增益 96% 落在非依赖型探针、检索门控 AUROC 0.530；`docs/18` 已引用该论文；12 天内定位漂移 5 次。详见 `CHANGELOG` 2026-11-16 |

## 四、质量保障

以自动验证替代人工确认。CI 在每次推送时执行分层、密钥扫描、离线回归、全链路、联动、插件启动等 18 套；
云端 `ops/verify.sh` 再跑一遍五件套。数字为 **2026-11-15** 实测：

| 套件 | 数量 | 覆盖范围 |
|---|---|---|
| 分层与规范 | — | 核心层不依赖框架、domain 不反向依赖、适配层不越界 |
| 离线回归 | 735 | 行为正确性（不联网、不读写生产库） |
| 联动体检 | 46 | 插件与核心层之间的调用契约 |
| 全链路 | 280 | 全部模块与端到端流程 |
| 通道无关层 | 7 | 流式顺序、typing、超时、补发 |
| 命令层 | 11 | 解析、权限、默认注册表 |
| 插件启动 | 7 | 7 个插件的真实加载 |

> 另有 engine 7、identity 6、delivery 25、approval 10、console 7、console e2e 9、
> 入站 6、包门面 5、kernel 7、面板 48。

## 六、风险与限制

| 风险 | 应对 |
|---|---|
| QQ 无个人号官方接口，依赖第三方 OneBot 实现 | 平台隔离在最外层；健康检查每 5 分钟探测登录；文档记录迁移路径 |
| 账号风控 | 建议独立账号；无法通过代码规避 |
| 飞书应用凭证泄露 | Secret 只存云端 keys.json（600）；可随时重置；scope 最小化 |
| 语音/embedding 供应商单点 | 语音已做智谱/DeepSeek 双 provider 互备；embedding 仍单点（待办） |
| 单用户环境 | 不以用户量作指标，以运行数据说明使用强度 |
| 记忆效果缺量化 | 影子采样、周报指标、判据与截止日期 |

## 七、设计原则

1. **决策附带数据**：每项取舍记录备选、依据与代价。
2. **影子实验必须有截止时间**：到期转正或移除。
3. **约定由工具强制**：分层、接口等约束实现为自动检查。
4. **优先处理静默失败**：不报错但让效果变差的问题，优先补可观测性。
