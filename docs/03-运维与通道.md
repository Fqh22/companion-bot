## 1 · 这台机器上跑着什么

一台 Linux（线上 2C4G），`systemd` + 本地 SQLite，不需要 GPU。

| 单元 | 作用 |
|---|---|
| `nonebot.service` | 机器人本体，`/opt/nonebot`，约 73MB / 6 个插件 |
| OneBot 后端 | 第三方实现，约 820MB / 端口 3001（具体后端见 §7） |
| `onebot-health.timer` | 每 5 分钟探测登录状态 |

内存底线 300MB。运行时根默认 `/opt`，由 `QQBOT_ROOT` 覆盖（`app_core/paths.py` 统一派生）。

## 2 · 部署

```bash
export QQBOT_HOST=ubuntu@<server>       # 含用户名；仓库里没有真实值
export QQBOT_KEY=<私钥路径>              # 不入库
bash ops/deploy.sh                       # 全流程
```
脚本从 **`git archive HEAD`** 导出，**必须先 commit**（否则部署旧 HEAD，只 WARN）。
顺序：快照 → 构建 `/opt/nonebot-releases/<sha>-<ts>` → release 内跑 `verify.sh --pre` →
`release-switch.sh activate`（停服务、`renameat2` 原子交换 `/opt/nonebot` 与候选目录）→
重启 → 全量 verify。验证失败时 live 与版本标记都不动；`--no-restart` 只构建验证。
`data/venv/config.yaml/.env` 在 `/opt/nonebot-shared`，ops 日志/state/ops.env 在
`/opt/nonebot-ops-state`，都不随版本走；`/opt/nonebot` 始终是真实目录（NoneBot 按
`resolve()` 算插件模块名，符号链接目录会算错）。
**只上传代码与脚本，不上传 `docs/`、CHANGELOG、README、任何密钥。**
回滚（版本目录天然保留新版本独有文件，不存在解包残留）：

```bash
ssh $QQBOT_HOST 'sudo bash /opt/nonebot/ops/release-switch.sh status'
ssh $QQBOT_HOST 'sudo bash /opt/nonebot/ops/release-switch.sh rollback <旧release-id>'
```
每次部署都会重启服务、打断对话，**按批次部署**，不要一项改动一次重启。

## 3 · 验证

```bash
ops/verify.sh            # 全量五件套：分层 + 离线回归 + 联动 + 全链路 + 插件启动
ops/verify.sh --pre      # 重启前：不碰生产库、不发消息
ops/verify.sh --quick    # 秒级：分层 + 联动
```

云端解释器是 `/opt/nonebot/venv/bin/python`（Python 3.12）；本机缺依赖时以云端 verify 为准，
CI 每次推送跑同一套。

| 时间 | 任务 |

| 03:40 / 04:00 / 04:05 / 04:30 | 复盘 / 间隔复习 / raw 清理 / 记忆清理 |
| 09:00 | 缺跑审计 |
| 每小时 | 知识索引 |
| 周日 20:30 / 21:00 / 21:10 | 话题巡检 / 周报 / 知识库审计 |
| 月 1 号 04:50 | 归档维护 |

补跑窗口 3–4 小时；root cron 在 03:17 / 03:40 / 03:50、周日 04:10 / 05:10、每 5 分钟健康检查。

告警阈值（2026-11-15 事故后定）：备份超 26h、脚本丢可执行位、本地拉取超 8 天、
演练超 8 天或从未做过；备份保留 7 天（本地 30 天、最多补 5 份）。
OneBot 掉线探测每 2 分钟、连续 2 次才告警、30 分钟内不重复。
统一告警面：`alerts.jsonl` + `/status` 一行显示 24h 计数。

## 5 · 备份与恢复

```bash
/opt/nonebot/ops/cloud-backup.sh          # 每日一致性导出（写 manifest.json）
tar xzf /opt/backup/cloud-<时间>.tgz -C /   # 恢复
ops/restore-drill.py                       # 恢复演练：按清单逐文件核对 + 真查库
```

备份包根目录有 `manifest.json`（逐文件 sha256/字节数 + 两个必需库的备份时行数）。
演练据此判：缺库 / 哈希不符 / 有数据恢复后为 0 行 → **失败**；备份时就是 0 行 →
`empty_by_design` 通过；无清单的旧备份按严格模式。`cloud-backup.sh` 缺必需库直接失败，
不再静默跳过产出「看着成功」的备份。代码包与 `deploy.sh` 对齐（含 `adapters/`），
演练会离线加载通道适配器；本地备份含密钥，目录必须在共享工作区外（见 `SECURITY.md`）。

异地备份 = 至少离开这块盘，三种方式任选：`BACKUP_PUSH_CMD`（任意命令，`{file}/{name}` 占位）、
rclone、coscli；配置在 `ops/ops.env`(600)。备份包**包含 `keys.json`**，按密件保管，
泄露后轮换全部 key 而不是回滚备份。月度维护手动跑 `purge.rotate` / `prune_old_packs`。

## 6 · 配置与运行观测

通过部署机上的共享 `config.yaml` 修改配置，修改前保留副本，通过 `ops/check-config-sync.py` 核对示例键，校验 YAML 无误后重启 NoneBot。
人格用 `/reload_persona` 加载，`watchlist.json` 在下次巡检读取。健康和运行日志用 `/debug` 与 `journalctl -u nonebot` 查看。

### 带走这个主体 / 看碎片候选（只读脚本）

```bash
# 主体快照（纯只读，SQLite mode=ro），输出目录可直接进 git
/opt/nonebot/venv/bin/python ops/export-subject.py
/opt/nonebot/venv/bin/python ops/export-subject.py --verify <导出的目录>
# 碎片整合候选报告（读取已有影子日志）
/opt/nonebot/venv/bin/python ops/consolidate.py --top 10
python ops/test-batch3-guards.py          # 导出往返与预算双模式自检
```

`export-subject.py` 输出 `persona.json`、`memory.jsonl`、`profile.json`、`relations.md`、
`corrections.md`、`followups.json`、`README.md` 与 `manifest.json`（每片 sha256 / 字节数 / 条目数）。
**不导出**向量 blob（换 embedding 后跑 `ops/rebuild-vectors.py --apply` 重建）、
`keys.json` / `config.yaml`（凭证与部署配置）、聊天历史（体量与隐私）。
旧的 `export-memory.py` / `export-persona.py` 仍按 cron 各导一半，主体快照是它们之上的完整层。

## 7 · 通道接入

| 通道 | 状态 | 说明 |
|---|---|---|
| **QQ / OneBot v11** | 可用，有风险 | 依赖第三方实现，逆向私有协议；只用独立小号 |
| **飞书** | 可用 | 企业自建应用 + 长连接，无需公网 IP / 域名；默认只与主人私聊 |

## 8 · 排障速查

| 症状 | 先看 |
|---|---|
| 不回消息 | `journalctl -u nonebot -n 50`；`/ping` |
| 记忆不写 | `/ping` 的配置状态；`admin.user_id` 是否配 |
| 定时任务没跑 | `job_runs` 表；`/debug`；`missing_jobs` |
| 语气 / 长度不对 | `data/prompt_log` 最近一条；`/prompt_last` |
| 通道断了 | `systemctl status onebot-health`；[02](02-系统与扩展.md) 的通道协议 |

```bash
journalctl -u nonebot -n 50
sqlite3 /opt/nonebot/data/chat.db "select * from job_runs order by ts desc limit 10"
sqlite3 /opt/qqbot-data/livingmemory.db "select count(*) from documents"
ops/replay-tone.py 16              # 语气改动怎么验
cat /opt/nonebot/.deployed_sha     # 云端现在跑的是哪个 commit
```

### 审计与主动消息（批次 4）

```bash
# 审计门面：两条都带 SUPERUSER，群里任何人碰不到
/audit                    # 最近 8 条副作用 + 可回滚标记 + 哈希链校验 + 待授权 id
/approve <id>             # 批准并重放执行（10 分钟内有效，过期自动作废）
python ops/test-batch4-guards.py
```

`data/audit.jsonl` 每行带 `prev_hash`，改中间一行会让后面全对不上；
`data/audit-pending.json` 是待授权请求（600）。`tools.require_approval` 默认 false：
写类工具照旧直接执行，但**每次都会记一条审计**；改成 true 后模型自己不能写入，
必须先由主人 `/approve <id>` 批准。`meme_send` / `web_open` 标记「不可回滚」——
消息发出去撤不回，不假装能撤销。

**主动跟进控制**支持直接说「这周先别问短租」「短租等我自己提」「不用跟进了」。可引用原问题或点名事项。近义说法结合最近对话识别；缺具体期限会询问。限时暂停到期后恢复候选资格，等待模式可说「恢复跟进短租」解除。**主动消息通道**：`proactive.channel` 默认 `qq`（现状）。改成 `feishu` 需要飞书插件启用、
且主人先跟它说过话（`data/feishu-chats.json` 存 open_id → chat_id，重启不丢）；
发不出去自动回退 QQ，不双发也不静默丢。批次 2 的宽松总上限 + 无进展超时是多段语音的前置：
`pacing.split_for_voice()` 按句切 300 字一段（最多 8 段），QQ 与飞书都逐段合成发送。
