## 1 · 这台机器上跑着什么

一台 Linux（线上 2C4G），`systemd` + 本地 SQLite，不需要 GPU。

| 单元 | 作用 |
|---|---|
| `nonebot.service` | 机器人本体，`/opt/nonebot`，约 73MB / 6 个插件 |
| OneBot 后端 | 第三方实现，约 820MB / 端口 3001（具体后端见 §7） |
| `config-ui.service` | 本地配置面板，只绑 `127.0.0.1:8110` |
| `onebot-health.timer` | 每 5 分钟探测登录状态 |

内存底线 300MB。运行时根默认 `/opt`，由 `QQBOT_ROOT` 覆盖（`app_core/paths.py` 统一派生）。

## 2 · 部署

```bash
export QQBOT_HOST=ubuntu@<server>       # 含用户名；仓库里没有真实值
export QQBOT_KEY=<私钥路径>              # 不入库
bash ops/deploy.sh                       # 全流程
bash ops/deploy.sh --no-restart          # 只上传 + 验证
bash ops/deploy.sh --skip-verify         # 仅紧急回滚时用
```

脚本从 **`git archive HEAD`** 导出，**必须先 commit**，否则部署的是旧 HEAD（只 WARN）。
顺序：云端代码快照（回滚点）→ 上传 `nonebot/` 与 `ops/` → 恢复可执行位、
写 `.deployed_sha` → `verify.sh --pre`（不过就不重启）→ `systemctl restart nonebot` → 全量 `verify.sh`。
**只上传代码与脚本，不上传 `docs/`、CHANGELOG、README、任何密钥。**

手工回滚：

```bash
tar czf /opt/backup/code-$(date +%Y%m%d-%H%M%S).tgz -C /opt/nonebot app_core plugins adapters
ls -t /opt/backup/code-*.tgz | head -3
tar xzf /opt/backup/code-<时间>.tgz -C /opt/nonebot
find /opt/nonebot -name __pycache__ -type d -exec rm -rf {} +
systemctl restart nonebot
```

每次部署都会重启服务、打断对话，**按批次部署**，不要一项改动一次重启。

## 5 · 备份与恢复

```bash
/opt/nonebot/ops/cloud-backup.sh          # 每日一致性导出
tar xzf /opt/backup/cloud-<时间>.tgz -C /   # 恢复
ops/restore-drill.py                       # 恢复演练：真解压、真查库
```

异地备份 = 至少离开这块盘，三种方式任选：`BACKUP_PUSH_CMD`（任意命令，`{file}/{name}` 占位）、
rclone、coscli；配置在 `ops/ops.env`(600)。备份包**包含 `keys.json`**，按密件保管，
泄露后轮换全部 key 而不是回滚备份。月度维护手动跑 `purge.rotate` / `prune_old_packs`。

## 6 · 配置面板

```bash
/opt/nonebot/venv/bin/pip install -r /opt/nonebot/ops/requirements-config-ui.txt
cp /opt/nonebot/ops/config-ui.service /etc/systemd/system/config-ui.service
systemctl daemon-reload && systemctl enable --now config-ui
cat /opt/nonebot/data/config-ui.token        # 只写一次，600
ssh -L 8110:127.0.0.1:8110 root@<server>    # 本机建隧道
# 浏览器打开 http://127.0.0.1:8110/?token=<token>
python ops/test-config-ui.py
```

面板按分组编辑 `config.yaml`（常用 14 项 / 高级 53 项，其中 15 项标高风险）、
两份人格、巡检话题；显示当前值 / 默认值 / 说明，保存前校验 + 自动备份 + diff，
保留 YAML 注释与顺序（`ruamel.yaml` round-trip）。

安全边界：只绑回环、校验 `Host` 与 `Origin`、token + `HttpOnly; SameSite=Strict` cookie、
不读 `keys.json`、不执行任意命令、原子替换。**不是公网后台。**
保存后：`config.yaml` 需 `sudo systemctl restart nonebot`；人格用 `/reload_persona`；watchlist 免重启。
v2 不做：一键重启、编辑 `keys.json`、公网访问、通用 JSON 编辑器。

## 8 · 排障速查

| 症状 | 先看 |
|---|---|
| 不回消息 | `journalctl -u nonebot -n 50`；`/ping` |
| 记忆不写 | `/ping` 的配置状态；`admin.user_id` 是否配 |
| 定时任务没跑 | `job_runs` 表；`/debug`；`missing_jobs` |
| 语气 / 长度不对 | `data/prompt_log` 最近一条；`/prompt_last` |
| 通道断了 | `systemctl status onebot-health`；[02](02-系统与扩展.md) 的通道协议 |
